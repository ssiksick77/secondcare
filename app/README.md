# 센터 회계대장 관리도구 — 사용 안내

`의료인공지능센터_지출장부_2026.xlsx`를 원본으로 쓰는 로컬 웹앱입니다. 엑셀 파일이 곧 데이터베이스이고, 앱은 그 파일을 읽고 씁니다. 엑셀에서도 언제든 열어 볼 수 있습니다.

## 1. 설치 (최초 1회)

필요한 것: Windows PC, Python 3.10 이상, 인터넷(패키지 설치 때만).

1. Python이 없으면 <https://www.python.org/downloads/> 에서 설치합니다. 설치 첫 화면의 **"Add python.exe to PATH"** 를 반드시 체크하세요. 체크하지 않으면 `python`을 입력했을 때 Microsoft Store가 열립니다.
2. 장부 파일 `의료인공지능센터_지출장부_2026.xlsx`가 `app` 폴더의 **바로 위 폴더**(`CAIH_회계장부_2026`)에 있어야 합니다. 다른 위치에 두려면 `.env`에 `LEDGER_XLSX=전체경로`를 적습니다.
3. `app\setup.bat`을 더블클릭합니다. Python 버전을 확인하고 패키지를 설치합니다. 병원망 프록시 때문에 실패하면 화면의 안내대로 `--proxy` 옵션을 씁니다.

## 2. 실행과 종료

- `app\run.bat` 더블클릭 → 콘솔 창이 뜨고 브라우저가 `http://127.0.0.1:8791` 로 열립니다.
- **콘솔 창을 닫으면 앱이 종료됩니다.** 쓰는 동안 최소화해 두세요.
- 이미 실행 중인데 다시 누르면 "이미 실행 중입니다" 안내와 함께 기존 창을 엽니다.
- 포트를 바꾸려면 `.env`에 `LEDGER_PORT=번호`.
- 설정 파일은 기본 `app\.env`이고, 환경변수 `LEDGER_ENV`로 다른 파일을 지정할 수 있습니다(상대 경로는 `app` 폴더 기준). 설정 화면의 저장도 그 파일에 씁니다.

### QA 장부로 실행하기

실제 장부·설정을 건드리지 않고 가상 QA 장부로 앱을 띄울 때는 `app\run_qa.bat`을 실행합니다.

- 장부: `docs\qa_data_2026_01_09\qa_ledger.xlsx` (`LEDGER_XLSX`). 파일이 없으면 실행하지 않습니다. xlsx 는 git 에서 제외되어 있으니 직접 복사해 둡니다.
- 설정: `docs\qa_data_2026_01_09\qa.env` (`LEDGER_ENV`). 비밀값 없이 `REQUEST_SUPPLIERS=알파몰,드림디포,가상문구A,가상문구B` 만 들어 있고, QA 중 설정 화면에서 저장한 값도 이 파일에만 기록됩니다. `app\.env`는 읽지도 쓰지도 않습니다(AI 키가 없으므로 AI 버튼은 꺼짐).
- 드라이브: `LEDGER_DRIVE_MOCK=1` — 증빙·첨부는 구글 드라이브 대신 로컬 폴더 `docs\qa_data_2026_01_09\qa_drive_mock\`(`LEDGER_DRIVE_MOCK_DIR`, 상대 경로는 `app` 폴더 기준)에 저장되고, QA 장부의 기존 증빙·첨부 미리보기도 이 폴더에서 읽습니다. `LEDGER_DRIVE_MOCK_DIR`가 없으면 기본값 `app\drive_mock\`.
- 포트: **8792** (`http://127.0.0.1:8792`). 실제 서버(8791)와 동시에 띄울 수 있습니다. 자동 백업은 `app\backup\qa_ledger_*.xlsx`로 따로 쌓입니다.
- MCP 는 QA 장부를 쓰지 않습니다(MCP 는 `app\.env`의 `LEDGER_XLSX`). MCP 로 QA 장부를 보려면 MCP 실행 환경에 `LEDGER_XLSX`·`LEDGER_ENV`를 같은 값으로 지정합니다.

**첫 실행 때 장부 구조가 자동으로 보정됩니다.** 재원·적립금·태그·증빙 시트가 추가되고 집행내역에 상태·증빙폴더·증빙목록·연결품의번호 열(연결품의번호는 비고의 `품의 X`에서 자동 이관), 품의내역에 상태 열, 예산변동에 국제공동연구개발비·연구개발부담비 열(맨 끝)이 생깁니다. 보정 전 파일은 `app\backup`에 백업되고 콘솔에 내용이 표시됩니다. 처음 실행하기 전에 장부 사본을 따로 보관해 두세요. 장부 파일에 차트·이미지·피벗이 있으면 저장 과정(openpyxl)에서 사라질 수 있으니 장부에는 넣지 마세요.

## 3. 처음 시작하기 (순서대로)

1. **재원 탭**에서 과제를 등록합니다. 재원코드는 거래번호(`YYYY-코드-NNN`)에 쓰이므로 짧게, `-` 없이.
2. **예산변동 탭**에서 재원별로 `이월`·`당초` 예산을 넣습니다. 변경은 회차 번호(1, 2, …)로 추가하며 앱이 다음 회차를 제안합니다. 같은 재원의 이월·당초는 한 건만 등록됩니다.
3. **태그 탭**(선택)에 센터 내부 계정을 등록합니다. 등록하면 입력 폼의 태그가 선택식으로 바뀝니다.
4. 오른쪽 위 **설정(톱니)** 에서 구글 드라이브를 연결합니다(증빙 업로드에 필요, 4절 참고).
5. AI 도우미는 선택이며 유료입니다(7절).

재원이 없거나 예산을 입력하지 않으면 대시보드 칸과 표에 '예산 미입력'이 표시됩니다. 1~2번을 먼저 하세요.

## 4. 화면 사용법

### 입력 폼 (집행·품의·적립금·예산·재원·태그)

- 필드 순서는 실무 입력 순서입니다: 날짜 → 재원 → 예산목 → 거래처 → 금액 → 적요 → 세목 → 태그 → 부가 정보. 처음 초점은 거래처에 있습니다.
- **Enter**는 다음 칸으로 이동, **Ctrl+Enter**는 저장, **Ctrl+Shift+Enter**(또는 "저장 후 계속" 버튼)는 저장하고 같은 종류의 다음 건을 바로 입력합니다. 이때 재원·예산목·날짜·사용자는 유지되고 거래처·금액·적요는 비워집니다.
- 입력 중 Esc나 취소를 누르면 "버릴까요?"를 묻습니다.
- 필수 항목이 비면 누락 항목을 모두 보여주고 첫 항목에 초점을 둡니다.
- **편집 모드**(집행내역 툴바): 현재 필터의 집행을 팝업 격자에서 엑셀처럼 고칩니다. 시트 열이 전부 보이고, 더블클릭·Enter·글자 입력으로 편집, Tab/방향키 이동, Shift+방향키 범위 선택, Ctrl+C 복사, Ctrl+V 로 엑셀에서 복사한 여러 행 붙여넣기, Ctrl+D 위 칸 채우기, Delete 비우기, Ctrl+Z 되돌리기. 맨 아래 빈 행에 입력하면 새 행이 되고, 체크 또는 '행 삭제 표시'로 삭제합니다. 거래번호·상태·연결 행의 핵심 열은 잠겨 있습니다. [저장]은 전부 성공 또는 전부 취소이며 오류 행은 붉은 띠로 표시됩니다. 셀 간 참조 수식·드래그 채우기·열 폭 조절은 지원하지 않습니다.
- 비고가 있는 집행은 적요 칸 왼쪽 위에 회색 메모 마크가 붙고, 마우스를 올리면 비고가 툴팁으로 보입니다(비고 열은 '상세 열'에서 켤 수 있습니다).
- 표의 행을 더블클릭하면 수정 창이 열립니다(집행내역은 한 번 클릭이 상세 패널, 두 번 클릭이 수정). 집행내역에는 작업 열이 없습니다. 삭제는 툴바 [삭제]를 누르면 나타나는 체크 열에서 여러 건을 골라 [선택 n건 삭제]로 한 번에 지우고(되돌리기 가능), 한 건은 상세 패널 맨 아래 [이 집행 삭제]로도 지울 수 있습니다.
- 금액 칸에 `=`로 시작하는 계산식을 넣을 수 있습니다(예: `=12000*3+500`, 사칙연산과 괄호만). 칸을 벗어나거나 저장할 때 계산돼 숫자로 저장됩니다.
- 저장 전에 같은 날·거래처·금액의 건이 있거나, 가용잔액을 넘거나, 금액이 음수이면 확인창이 뜹니다(차단은 아님). 적립금 '사용'도 잔액을 넘으면 확인창이 뜹니다.
- 인건비 확정·적립금 기록·품의 전환으로 생긴 집행은 거래번호 옆에 **인건비 / 적립 / 품의** 배지가 붙고, 누르면 원본 화면으로 이동합니다. 인건비·적립 연결 행은 재원·예산목·금액·거래처·원인발생일이 잠기며(세목·태그·관리번호·날짜·비고만 수정) 삭제는 원본 화면에서만 할 수 있습니다.
- 새 폼의 날짜는 항상 오늘이고, '저장 후 계속'으로 이어 입력할 때만 직전 날짜가 유지됩니다.
- 삭제·확정 취소·청구/완료 처리 뒤 토스트의 **되돌리기**(12초)를 누르면 직전 저장 전 상태로 복구합니다. 그 사이에 다른 창·MCP·엑셀이 장부를 바꿨으면 거부됩니다. 그 뒤에는 app/backup 폴더의 백업 파일로 복원하세요.
- 집행 상세 패널이 열리면 표의 부수 열(날짜 버튼·재원·세목·태그·증빙·비고)을 접어 거래번호·상태·예산목·거래처·적요·금액만 남깁니다.
- 금액에 쉼표를 넣어도 됩니다. 폼의 금액 칸에서 `=`로 시작하는 계산식(예: `=12000*3+500`)은 계산되어 저장되지만, 엑셀 파일 안의 수식 셀(엑셀에서 직접 넣은 `=SUM(…)` 등)은 앱이 값으로 읽지 못합니다(6절 끝 참고).

### 집행내역 탭

- **상태** 열: 발생(원인발생일) → 청구(지급청구일) → 보완(직접 표시) → 승인(지출완료일) → 완료(결의일 등록). 날짜가 우선이며 '보완'만 수동입니다. 표에는 원인발생일만 '발생일'로 보이고 나머지 날짜는 행을 클릭한 상세 패널에서 봅니다. 상태 칸 옆의 체크(✓) 버튼이 오늘 날짜로 다음 단계(청구→승인→결의=완료)를 등록합니다. 상태 칸 아랫줄에는 그 단계의 날짜가 보이고, 청구 단계에서는 '보완'/'해제' 링크로 보완을 켜고 끄며, 단계 되돌리기·날짜 지정은 상세 패널의 처리 단계 타임라인에서 합니다. 결의를 바로 등록하면 비어 있는 청구일·완료일도 같은 날짜로 채워집니다.
- 상태 칸의 버튼: 칸 안의 체크(✓)는 오늘 날짜로 다음 단계(청구 → 승인 → 결의)를 등록하고, 청구 단계에서는 날짜 옆 **보완** 링크로 보완 표시를, 보완 단계에서는 **해제** 링크로 해제를 합니다. 완료된 건에는 체크가 없습니다. 승인·결의를 취소하려면 행을 클릭해 상세 패널 타임라인에서 그 단계 날짜를 지웁니다(뒤 단계부터).
- 상단 타일(발생·보완·승인·증빙 없음·완료)을 누르면 해당 건만 필터됩니다.
- 적요 칸 아래에 거래처가 작은 글자로 붙고(ref 집행현황 구조), 결제수단 열은 품의와 같은 목록(연구비카드·계좌이체·연구자선지출·공금통장·적립금·기타)을 씁니다. 품의→집행 전환 시 결제수단이 넘어오고, 인건비 확정 집행은 계좌이체, 청구일·완료일·결의일=지급일로 기록됩니다.
- 열 머리글을 누르면 정렬됩니다. 검색은 쉼표를 무시합니다(150,000 = 150000). "상세 열"을 켜면 관리번호·세세목·사용자·비고 열이 보입니다. 작업 열은 오른쪽에 고정되어 가로 스크롤을 해도 보입니다.
- 행을 클릭하면 오른쪽 상세 패널(560px)이 열립니다. 한 건을 끝까지 처리하는 작업대로, Esc나 다른 탭으로 이동하면 닫힙니다.
  - **이전/다음 건**: 머리의 ↑·↓ 버튼(또는 패널 안에서 ↑↓·PageUp/PageDown 키)으로 지금 표에 보이는 순서대로 옆 건으로 넘어가며, 표의 선택 행도 따라 움직입니다. 옆의 `n / N`은 현재 위치입니다.
  - **처리 단계 타임라인**: 발생 → 청구 → 승인 → 결의(등록되면 '완료')가 점과 선으로 보이고, 끝난 단계 아래에 날짜가 있습니다. 다음 단계에는 [오늘 등록]과 '날짜 지정'(날짜를 골라 저장)이 있습니다. 끝난 단계의 날짜를 누르면 그 자리에서 바꿀 수 있고, 지우면 단계 취소입니다(뒤 단계가 있으면 먼저 뒤 단계를 취소). 승인·결의를 지정하면 비어 있는 앞 단계 날짜도 같은 날로 채워집니다. 청구 단계에서는 '보완' 체크로 보완을 켜고 끕니다(붉은 점). 인건비·적립금 연결 행의 원인발생일은 바꿀 수 없습니다.
  - **집행 정보**: 결제수단·세목·세세목·태그·사용자·관리번호·비고는 값을 누르거나 Enter로 그 자리에서 고칩니다(Enter 또는 칸을 벗어나면 저장, 비고는 Ctrl+Enter, Esc 취소, 값이 같으면 저장하지 않음). 재원·예산목·금액·거래처·적요는 [수정] 창에서 바꿉니다. 모든 저장은 알림의 [되돌리기]로 취소할 수 있습니다.
- **CSV 저장** 버튼은 현재 필터의 목록을 파일로 저장합니다.

### 지출결의서 (집행 1건 = 1장)

### 품의내역 탭

품의는 집행 전 계획입니다. **[집행전환]**을 누르면 품의 값이 채워진 집행 입력 폼이 열리고, 저장하는 순간 집행이 생성되며 품의 상태는 `집행완료`로 바뀝니다. 폼을 취소하면 아무것도 바뀌지 않습니다. 전환된 품의는 삭제할 수 없습니다(감사 추적). 전환된 집행에는 **`연결품의번호`** 열에 품의번호가 기록되고(화면·API·MCP 수정으로는 바뀌지 않는 시스템 열), 호환을 위해 비고에도 `품의 번호`가 남습니다. 비고는 자유롭게 고쳐도 연결이 끊기지 않습니다. 이전 장부는 첫 실행 때 비고가 `품의 X`로 시작하고 품의내역에 X가 있는 집행에 연결품의번호를 채웁니다(열이 이미 있으면 다시 채우지 않음). 품의 배지·지출결의서는 연결품의번호를 먼저 보고, 비어 있으면 비고의 `품의 X`를 씁니다.

### 적립금 탭

**거래처 탭**(2026-10-19): 적립금 거래처와 **코드**(한글·영문·숫자 2~6자, 중복 불가)를 관리합니다. 코드는 적립번호 앞자리(`코드-적립-2026-001`, `코드-사용-2026-001`)와 주문번호 앞자리에 쓰이며, 번호에 한 번 쓰이면 바꿀 수 없고 적립금에 쓰인 거래처는 지우거나 이름을 바꿀 수 없습니다. 등록되지 않은 거래처로 적립금을 저장하면 저장은 되고 이름 앞 글자(겹치면 더 길게)로 코드를 자동 등록하면서 안내를 띄웁니다. 적립금 폼의 거래처 자동완성은 등록 거래처를 먼저 보여 줍니다.

**단계(2026-10-19)**: 사용 행은 `발주일` → `결제일` → `수령일`로 단계가 정해지고 표의 `상태` 열에 대기/발주/결제/수령 배지로 보입니다(집행의 발생→청구→승인→결의와 같은 방식). 새 사용 행은 발주일이 비어 있으면 일자로 채워 '발주'에서 시작하고, 이전 장부의 사용 행도 앱이 켜질 때 같은 규칙으로 보정합니다. 상태 열의 체크(또는 상세 패널의 [오늘 등록])는 다음 단계 날짜를 오늘로 적고, 앞 단계가 비어 있으면 같은 날로 채웁니다. 뒤 단계 날짜가 있으면 앞 단계를 비울 수 없습니다(먼저 뒤 단계 취소). 적립 행에는 단계가 없습니다(상태 "–"). 상세 패널은 적립금 행을 눌러 열고, 단계 날짜 칸을 눌러 바로 고칠 수 있습니다. 도구바의 상태 필터로 단계별로 볼 수 있습니다. API: `POST /api/deposit/{row}/action` (order|pay|receive|unorder|unpay|unreceive).

거래처별 선결제 잔액을 관리합니다. **적립**을 추가할 때 "집행내역에 기록"을 켜면 집행내역에 선결제 한 건이 생성되어 예산에서 차감되고, 적립 행의 `연결거래번호`에 기록됩니다. **사용**은 잔액만 줄입니다. 연결된 적립 행을 삭제하면 연결 집행도 함께 삭제됩니다(확인창). 태그는 사용 건에 붙입니다.
소모품 **주문**이 남긴 '사용' 행(증빙번호 = 주문번호, 적요 "소모품 주문 …")은 주문과 묶여 있어 증빙번호·금액·거래처·구분을 고치거나 행을 지울 수 없습니다("주문 X에 연결된 적립금 기록입니다. 주문 보기에서 주문을 취소하면 함께 삭제됩니다."). 적요·사용자·비고·태그는 고칠 수 있습니다. `/api/all`의 적립금 행에 `_locked_by`(주문번호)가 붙어 화면이 잠금을 표시합니다.

### 대시보드

- **예산** 탭: 위에서부터 예산목별 가용잔액 칸(큰 숫자 = 예산현액 − 집행 − 품의대기, 막대 = 집행률, 회색은 품의대기; 재원 필터가 '전체'면 합산) → 월별 집행 추이(막대 + 남색 누적선, 예산현액 기준선) · 거래처별 적립금 잔액 → 재원×예산목별 집행 현황 표. 전체 합계(예산현액·집행·집행률·품의대기·가용잔액·미승인)는 필터 줄 오른쪽 한 줄에 나옵니다. 잔액·가용잔액·집행률은 연·월 필터와 무관하게 파일 전체 기준이고(대기 품의도 날짜와 무관하게 전부 차감), 연·월 필터는 **집행액** 열에만 적용됩니다. **월**을 고르면 당월 집행과 연초~당월 누계를 함께 보여줍니다. 재원 목록에 없는 재원(외부 인건비 지급처, 엑셀에서 직접 넣은 재원 등)이나 예산목 목록 밖의 집행·대기 품의는 예산 집계에서 빠지며 필터 줄의 "집계 제외 n건"을 눌러 확인할 수 있습니다. API·MCP 대시보드도 같은 규칙입니다(9절 집계 규칙).
- **태그** 탭: 집행내역(적립 선결제 건 제외) + 적립금 사용 건을 태그별·분류별·월별로 집계합니다. 예산 집계 집행액과의 차이는 표 위 "조정" 줄에 나옵니다.
- **CSV 저장**, **인쇄** 버튼으로 마감 자료를 뽑습니다.

- **소모품 주문**: 소모품 탭에서 승인된 건을 체크하고 [주문 생성]을 누르면 주문일·구매처(기본: 신청의 구매처)·결제금액(기본 주문금액)·**적립금 사용**(기본 켬)·사용자·비고를 확인한 뒤 주문 1건이 **장부에 기록**됩니다(쇼핑몰 주문은 발주서를 보고 따로 넣습니다). **한 주문에는 구매처가 같은 신청만** 묶을 수 있습니다(섞어 고르면 [주문 생성]이 꺼지고 "구매처가 같은 신청만 한 주문으로 묶을 수 있습니다"가 보이며, 서버도 거부). 주문의 구매처는 신청의 구매처와 같아야 하고, 바꾸려면 화면에서 확인한 뒤 `extra.vendor_override=true`로 보내며 이때도 설정의 구매처 목록에 있는 이름이어야 합니다(오타·목록 밖 이름·주문번호 앞자리로 쓸 글자가 없는 이름은 거부). API는 `extra.구매처`(또는 이전 이름 `거래처`)를 받습니다. 주문번호는 구매처에 따라 `알파-YYYYMMDD-NN`(알파몰), `드림-YYYYMMDD-NN`(드림디포), 그 밖에는 구매처 이름의 한글·영문·숫자 앞 두 글자입니다. **취소한 번호는 다시 쓰지 않습니다**(숨김 `메타` 시트에 앞자리·날짜별 최고값 `주문번호최고-알파-20261014`). 적립금 사용을 켜면 적립금 탭에 그 구매처의 '사용' 1건(거래처 열 = 구매처, 적요 "소모품 주문 …", 증빙번호 = 주문번호)이 함께 기록됩니다.
  - **검사·경고**: 결제금액·주문금액은 원 단위 정수만(1.5원 거부, 오류에 칸 이름). 적립금 사용인데 결제금액이 0원이면 "결제금액이 0원이면 적립금 사용 기록을 남길 수 없습니다. 적립금 사용을 끄세요." 주문일은 묶인 신청의 결재일보다 빠를 수 없고, 배송일은 주문일보다 빠를 수 없습니다. 결제금액이 주문금액보다 크거나 사용 후 그 구매처의 적립금 잔액이 음수가 되면 저장은 하고 응답의 `warnings: [문구…]`로 알려 줍니다(화면은 보내기 전에 확인창).
  - **주문 취소와 적립금**: 취소는 배송일이 없는 주문만 됩니다("배송일이 있는 주문은 취소할 수 없습니다. 먼저 [배송일 지우기]를 누르세요."). 주문의 적립금사용이 Y일 때만, 증빙번호 = 주문번호이고 적요 "소모품 주문 {번호}"인 '사용' 행(없으면 금액 = 결제금액인 행) **1건**을 지웁니다. 수기로 넣은 다른 행은 건드리지 않습니다. Y인데 그 행을 못 찾으면 응답의 `deposit_missing: true`로 화면이 경고합니다(응답: `cancelled, deposit_removed, deposit_missing, released`). 주문은 소모품 탭의 **주문** 보기에서 다룹니다(아래). 주문 생성 뒤에도 화면은 신청 보기에 머뭅니다. 주문 묶음을 품의로 올릴 때는 패널의 [품의 전환]이 같은 주문의 승인 건을 한꺼번에 묶습니다.
- **소모품 2단 메뉴 [신청 | 주문] (담당자)**: 소모품 탭을 고르면 탭 막대 바로 아래에 **신청 · 주문** 줄이 생깁니다(←/→ 키로 이동, 고른 보기는 이 브라우저에 기억). 연구원 화면에는 이 줄이 없고 늘 신청 목록입니다.
  - **신청** 보기: 지금까지의 목록·필터·처리 막대([주문 생성] 포함)·상세 패널 그대로입니다.
  - **주문** 보기: 주문 표만 전체 폭으로 보입니다. 연도(탭 막대의 연도와 같음)·구매처·상태(배송 전 = 배송일 없음 / 배송 완료)·검색(주문번호·신청번호·품목)으로 거르고, 오른쪽에 `n건 · 주문금액 합계`가 보입니다. 열: 주문번호, 주문일·배송일(MM/DD, 전체 날짜는 툴팁), 구매처, 주문금액, 결제금액, 적립금, 건수, 구매내역(첫 신청의 품목 + "외 n건", 누르면 그 신청 상세, 툴팁에 전체 목록), 작업. 배송 전 주문은 배송일 칸의 [등록]으로 배송일을 넣고, 작업 열에서 [발주서]·[주문 취소](배송 전만: 신청의 주문 해제 + 그 주문의 적립금 사용 기록 삭제, 쇼핑몰 주문은 따로 취소)를 합니다. 배송된 주문은 작업 열의 [배송일 지우기]로 배송일만 지웁니다(묶인 신청은 완료 → 승인 표시). 취소한 주문은 행이 지워지므로 따로 '취소' 상태는 없습니다. 신청번호를 누르면 신청 보기로 가서 그 신청의 상세 패널이 열립니다(목록 필터에 가려져 있으면 필터를 풀고 그 연도로). 하위 탭 **주문** 옆 숫자는 배송 전 주문 수(연도 무관)입니다.
- **발주서 (독자 = 공급처, 2026-10-14 결정 D2)**: 주문의 [발주서]를 누르면 쇼핑몰에 보낼 인쇄용 발주서가 열리고 [인쇄]는 발주서만 A4 세로로 인쇄합니다. 머리글은 **발주기관**(우리 센터, 설정 `REQUEST_BUYER`)·**공급처**(주문의 구매처)·배송지·담당자(설정 › **신청 · 발주서**). 줄마다 순번·온라인코드·상품코드·품목·규격·수량·단가·공급가액·부가세·금액, 아래에 공급가 합계·부가세·총액(= 주문금액). 적립금 정보는 넣지 않고, 신청번호는 원내용 `internal`로만 옵니다(화면이 작은 "내부" 열로 표시). API `GET /api/request/order-sheet/{주문 행}` → `{order, lines[{…, internal:{신청번호, 신청인, 관련과제}}], internal[], totals:{공급가합계, 부가세, 총액}, total, vat_total, header:{발주기관, 공급처, 배송지, 담당자}, settings}`(`settings`는 이전 이름 호환).
- **첨부**: 상세 패널에서 견적서·인보이스·요금제 안내 등을 올립니다(증빙과 같은 구글 드라이브 계정). 저장 위치는 `내 드라이브 / 신청 / YYYY / 신청번호 /`, 파일명은 `신청번호_품목_원본이름`(확장자도 금지 문자 제거)이며 이미지는 미리보기가 보입니다. **서버 규칙**: 올리기는 신청·반려·승인 상태에서만, 파일당 25MB, 신청 1건에 **20개 · 합계 100MB**까지(넘으면 413, 아무것도 올리지 않음). 지우기는 신청·반려 상태에서만, 승인 상태는 담당자 화면(`extra.admin=true`, 보안 장치 아님)만. 품의전환·완료는 올리기·지우기 모두 불가. 업로드 폼에 `expect`(JSON 문자열 `{신청번호, _snapshot}`, 선택)를 보내면 열린 패널이 보던 행과 다를 때 404로 거부합니다. 첨부가 있는 신청을 지우면 첨부도 함께 지우고 드라이브 휴지통으로 옮깁니다.
- **견고성**: 전환·주문 API의 `rows`는 정수 행 번호 목록이어야 합니다(`["abc"]` 등은 400 "선택한 신청의 행 번호가 올바르지 않습니다"). 장부 파일이 다른 프로그램·공유 설정 때문에 열리지 않으면(PermissionError) 경로를 드러내지 않고 423 "장부 파일을 열 수 없습니다…"로 답합니다.
- 시트: `신청`, `주문`, `신청첨부` (없으면 자동 생성).

#### 학회 여비 계산기 (`static/conf.js`)

학회 신청 폼의 **[여비 계산기]** 로 엽니다. `ref/학회여비계산기V2.html`의 규정값과 산식을 옮겨 새로 작성했습니다(근거: 공무원 여비 규정, 대통령령 제36492호, 2026.7.1. 시행. 규정값은 `conf.js` 맨 위 `REG` 한 곳에 모여 있어 개정 시 그 객체만 고칩니다). 연구원·담당자 모두 쓸 수 있고, 연구원은 신청 상태일 때만 고칠 수 있습니다(기존 수정 규칙과 같음).

- **입력**: 출장 구분(국외/국내, 신청 폼에서 고른 값으로 시작), 직급(여비지급) 구분(차관급·1급은 체크해야 보임), 국가·도시 검색(목록에서 고르면 가·나·다·라 등급 자동 선택, 별표4 비고2), 도시 등급, 국내는 숙박 지역(서울 10만·광역시 8만·그 밖 7만 원/박), 환율(원/USD)과 기준일, 학회 기간, 이동 구간, 운임, 숙박비 결제액, 학회 제공 식사 끼니, 등록비·논문 인쇄비·기타, 외부 지원금. 금액마다 통화를 고르며(₩·USD·EUR·JPY·GBP·CNY·CHF·SGD·HKD·TWD·AUD·CAD, 국내는 ₩ 고정) 외화는 환율로 원화 환산합니다. USD 외 통화를 고르면 그 통화의 환율 칸(원/1단위)이 환율 줄에 추가되어 통화별로 한 번만 입력합니다. 처음 열면 신청 폼의 국내/국외·기간·장소·등록비로 시작값을 채웁니다.
- **이동 구간 (시간대 환산)**: 구간마다 출발·도착 각각 장소, 시간대, **현지** 일시를 넣습니다. 시간대는 자주 가는 지역(서울·도쿄·베이징·홍콩·싱가포르·방콕·인도·런던·파리·베를린·뉴욕·시카고·덴버·LA·토론토·상파울루·시드니 등)을 묶은 목록에서 고르고, 없으면 **기타 (IANA 이름 직접 입력)** 에 `Europe/Lisbon` 같은 이름을 넣습니다(브라우저 `Intl.DateTimeFormat`으로 검사, 틀리면 빨간 테두리와 함께 계산이 멈춤). 장소에 도시 이름을 쓰면 시간대를 자동으로 골라 줍니다(직접 고른 시간대는 바꾸지 않음). 현지 일시는 서머타임까지 반영해 UTC 순간으로 환산하고(외부 라이브러리 없이 반복 보정, 서머타임 시작으로 없는 시각은 1시간 뒤로 보정하고 주의 표시), 표에 **현지 시각과 한국 시각(KST)** 을 나란히 보여 줍니다.
- **기내박은 구간의 현지 날짜, 여행일수는 한국 시각 기준으로 셉니다(2026-10-16 변경).** 기내박 = 항공·선박 구간에서 출발 현지 날짜 → 도착 현지 날짜가 바뀐 횟수(제16조, 철도·자동차는 차감 안 함. 미주에서 서쪽으로 귀국하는 편도 실제 기내 밤 수와 같음). 여행일수 D = 첫 출발일부터 마지막 도착일까지의 한국 날짜 수(양 끝 포함). 시간대를 환산했더니 도착이 출발보다 빠르거나 같으면 주의를 띄우고 그 구간 기내박은 0박으로 둡니다. 실제와 다르면 **기내박 직접 입력**으로 덮어씁니다. 이 기준은 산출 내역 아래와 인쇄물에 함께 적힙니다. (현지 날짜로 세는 원본 계산기와 서쪽·동쪽 방향 비행에서 ±1박 차이가 날 수 있습니다. 숙박비는 결제액 한도이므로 상한만 영향)
- **산식** (항목별 원 미만 절사 후 합산): 일비 = 1일 정액 × D, 단 현지 도착 다음 날부터 세어 15일 초과 30일까지 90%, 60일까지 80%, 그 뒤 70%(제17조, 일비만 감액). 식비 = 1일 정액 × D − 제공 끼니(기내식 + 학회 제공) × 1일 식비/3. 숙박비 = min(결제액, 1박 상한 × 인정 박수), 인정 박수 = (D − 1) − 기내박, 국내 제1호는 실비 전액. 운임·등록비·인쇄비·기타는 실비. 총 지급 예상액 = 여비(운임+일비+숙박비+식비) + 부대비 − 외부 지원금(제28조, 0원 아래로 내려가지 않음).
- **결과**: 위쪽 요약 띠(총 지급 예상액·여비·부대비·외부 지원 차감·일수·박수·등급), 산출 내역 표, 안내(숙박 상한 초과·식사 차감·장기체재 감액·좌석 등급·중복 신청 금지·정산 기한 = 귀국 다음 날부터 2주), 제출 서류 체크리스트(국외: 참석 전·후, 국내 별도, 체크 상태도 저장), 참고용 안내 문구. 입력이 덜 되면 '계산하려면' 목록이 보이고 [금액에 적용]이 꺼집니다.
- **저장**: [금액에 적용]을 누르면 신청 폼의 금액이 합계로 바뀌고 잠깁니다(기간·국내/국외·등록비 칸도 맞춰 채움). 신청을 저장하면 `상세` JSON에 `{v:2, in:{입력, fxs:{통화별 환율}}, out:{합계, 여비, 부대비, 외부지원, 일수, 박수, 기내박, 등급, 환율, 환율표, 기준:"KST", lines, docs, …}}`(v:1 저장분도 그대로 읽음) 와 맨 위 `합계`가 함께 들어가고, 금액 = 합계로 저장됩니다. **계산 초기화**(계산기 또는 폼의 버튼)는 계산 결과를 지우고 금액 잠금을 풀어 직접 입력하게 합니다(저장해야 반영).
- **상세 패널**: 계산이 있는 학회 신청은 '여비 계산' 줄에 일수·박수·등급·합계가 보이고 **산출 내역 보기**를 누르면 계산기가 보기 전용으로 열립니다(품의전환·완료로 잠긴 신청은 폼의 버튼도 '산출 내역 보기'로 바뀜). 보기 전용에서 저장된 합계와 현재 규정으로 다시 계산한 합계가 다르면 알려 줍니다.
- **필수 입력은 기본 정보뿐**(2026-10-16): 국외는 도시 등급과 환율(원/USD), 국내는 숙박 지역. 이동 구간과 금액 칸은 비워도 됩니다.
- **출장 기간과 학회 기간은 따로 적습니다**(2026-10-16): 기본 정보의 출장 시작일·종료일이 일수(D)의 기준입니다. 비우면 이동 구간의 한국 날짜에서, 그것도 없으면 학회 기간에서 유도하고 안내 문구를 붙입니다(둘 다 없으면 0일, 입력 금액만 합산). 이동 구간은 기내박 계산에 쓰고, 구간으로 계산한 기간이 입력한 출장 기간과 다르면 주의를 띄웁니다. 출장 기간이 학회 앞·뒤로 각 1일을 넘으면 "학회 전후로 각 1일씩만 출장으로 인정됩니다" 주의가 붙고, 넘는 날은 **공제일수**로 자동 계산해 **일비·식비**에서 뺍니다(지급 일수 = 출장일수 − 공제일수, 산식에 "9일 − 공제 4일 = 5일"처럼 표시, 장기체재 감액도 인정 출장일 범위에서만 셈). 숙박 박수는 공제하지 않습니다. 상세 JSON `out`에 `공제일수`·`지급일수`가 저장됩니다. 구간을 쓰다 만 칸(일시·시간대 누락)은 여전히 채워야 합니다.
- **조작**: Enter 는 다음 칸, **Ctrl+Enter** 는 [금액에 적용]. 입력을 바꾼 뒤 Esc·[취소]를 누르면 버릴지 한 번 묻습니다. 계산기가 열린 채 Ctrl+P 를 누르면 뒤 화면이 아니라 산출 내역이 인쇄됩니다. 출장 구분을 국내로 바꾸면 시간대·한국 시각·기내박 열이 숨고 모든 일시를 한국 시각으로 봅니다(국외로 되돌리면 통화·환율·시간대 입력이 그대로 남음). 국내 선택 중에는 결제 통화가 모두 ₩로 계산됩니다.
- **서버 규칙**: 계산 결과(v·in·out)가 있는 신청은 서버가 금액을 산출 합계로 강제하고(API·MCP 경로 포함), 상세의 `합계`와 `out.합계`가 다르면 거부합니다. 학회 금액은 원 단위 정수, 0원은 저장은 되지만 승인할 수 없습니다. 승인된 학회 신청의 상세(기간·장소·산출 내역)가 바뀌면 금액이 같아도 다시 승인받습니다. 신청 폼의 출장 구분(국내/국외)은 필수이며 기본값이 없습니다.
- **인쇄**: [인쇄]는 산출 내역만 A4 세로로 인쇄합니다(발주서와 같은 양식): 기본 정보(신청번호·신청인·학회명·직급·등급·환율·기간·이동 구간 현지/한국 시각), 산출 내역, 안내, 제출 서류 체크리스트, 유의 문구, 확인자 서명란.
- **제외**: 원본 계산기의 **관용(공용)차량** 항목(일비 1/2)은 넣지 않았습니다(사용자 결정). 입력값 파일 저장·불러오기와 엑셀 내보내기도 신청 `상세`에 저장되므로 넣지 않았습니다.

### 연 단위 운영 (2026-10-13 결정)

장부 파일 하나에 한 해의 데이터만 둡니다. 해가 바뀌면 새 파일을 만들고 `.env`의 `LEDGER_XLSX`를 바꿉니다. 재원·태그·인원·지급처 같은 기준정보는 새 파일에 다시 등록(또는 시트 복사)하고, 예산변동의 '이월' 회차와 인원의 '이월선급'에 전년도 잔액을 넣습니다. 대시보드·인건비의 연도 필터는 같은 파일 안의 연도 구분용이며, 파일을 연도별로 나누면 예산(전 기간 합계)과 집행(연도 필터)의 기준 차이가 생기지 않습니다.

## 5. 증빙 관리 (구글 드라이브)

집행 행의 상세 패널에서 증빙 파일을 올리고 지웁니다. 증빙 표에는 이미지 파일(jpg·png·gif·webp)의 작은 미리보기가, 그 밖의 파일(PDF·HEIC 등)에는 확장자 칩이 보이며, 파일명을 누르면 드라이브에서 새 창으로 열립니다. 표의 열은 미리보기 · 증빙(종류, 아래에 회색 증빙번호) · 파일(파일명, 아래에 원본 이름·크기·업로드일, 파일 없는 항목은 "파일 없음") · 비고 · [양식] [파일 첨부] [삭제]입니다. 업로드는 증빙종류·날짜·비고·파일을 고르고 [업로드]하거나 파일을 끌어다 놓으면 바로 올라갑니다.

- 저장 위치: 내 드라이브 / 증빙관리 / YYYY / 재원코드 / 거래번호 / (첫 업로드 때 자동 생성)
- 파일명: `재원_증빙종류_금액_YYMMDD.ext` (같은 이름이 있으면 `_2`, `_3`). 날짜는 업로드 폼의 "파일명 날짜"(기본값 원인발생일). 적요는 넣지 않습니다(2026-10-20: 이름을 짧게, 내부 메모가 제출 서류에 노출되지 않게). **집행의 재원·금액을 고치면** 그 건의 드라이브 파일 이름과 장부 파일명이 규칙대로 따라 바뀝니다(날짜·확장자 유지, 결과는 저장 알림에 표시). MCP `update_row` 로 고친 경우는 다음에 화면에서 저장할 때까지 이름이 그대로입니다.
- **적립금 거래의 증빙**(2026-10-19): 적립금 탭에서 행을 누르면 같은 모양의 상세 패널이 열리고, 집행과 똑같이 증빙을 올리고·실물만 항목을 만들고·지웁니다. 적립금 행마다 `적립번호`(`거래처코드-적립|사용-YYYY-NNN`, 거래처·구분·일자 연도별 일련번호, 자동 부여·불변)가 있고 증빙 시트의 `거래번호` 칸에 이 번호가 들어갑니다. 저장 위치는 내 드라이브 / 증빙관리 / YYYY / 적립금 / 거래처명 / 적립번호 /, 파일명은 `거래처_증빙종류_금액_YYMMDD.ext`(날짜 기본값은 일자, 거래처·금액을 고치면 따라 바뀜). 증빙이 있는 적립금 행은 지울 수 없습니다. 이전 장부의 적립금 행은 앱이 켜질 때 일자 순으로 번호를 채웁니다. 적립금의 `증빙번호` 열(영수증·주문 번호를 손으로 적는 칸)은 그대로이고 증빙 파일과는 별개입니다.
- 장부 기록: `증빙` 시트와 집행내역의 `증빙폴더`(폴더 링크), `증빙목록`(종류 요약) 열
- 삭제하면 장부에서 지우고 드라이브 파일은 휴지통으로 보냅니다(30일 뒤 영구 삭제). 여러 파일을 올리다 중간에 실패하면 그 요청에서 올린 파일은 모두 되돌립니다.
- **드라이브와 맞추기**(2026-10-19/20): 상세 패널에서 증빙 목록을 불러올 때마다 드라이브에 각 파일의 현재 상태를 물어, 이름이 바뀌었으면 장부의 파일명을 그 이름으로 고치고(원래 이름은 남기지 않음), **드라이브에서 지웠거나 휴지통에 있는 파일은 그 증빙 항목을 장부에서 지웁니다**(드라이브가 기준). 집행내역 탭의 **[드라이브 동기화]**는 같은 일을 모든 증빙에 한꺼번에 하고, 거래번호 재부여로 어긋난 드라이브 폴더 이름도 현재 번호로 고칩니다. 앱 권한(drive.file)상 앱이 올리지 않은 파일(드라이브에 직접 넣은 것)은 보이지 않습니다.
- 증빙종류는 자유 입력이며 이전 값이 자동완성됩니다.
- 앱은 자기가 만든 파일만 접근합니다(`drive.file`). 드라이브에서 '증빙관리' 폴더를 옮기거나 지우지 마세요.

### 집행 취소 (2026-10-19)

집행 상세 패널 아래의 [취소]로 집행을 취소합니다(사유는 선택, 보완·취소 이력에 남음). 취소 건은 행이 '취소' 상태로 남되 **집행액·가용잔액·'예산목 잔액' 열·대시보드·태그 집계·결의서 재원 현황·AI 보고서·MCP 대시보드 어디에도 금액이 들어가지 않습니다**(표에서는 흐리게, 금액에 취소선). 결의서는 만들 수 없고 청구·승인·결의 단계 처리도 막힙니다. 상태 열의 [해제] 또는 패널의 [취소 해제]로 되돌리면 날짜대로 상태가 돌아오고 다시 집계됩니다. 인건비·적립금에서 생긴 연결 집행은 취소할 수 없습니다(원본 화면에서 처리). 빠른 필터 타일 '취소'로 모아 볼 수 있습니다. API: `POST /api/exec/{row}/action` (cancel | uncancel, extra.사유 선택).

### 증빙 복사 — 한 문서를 여러 거래에 (2026-10-20)

사전결재안처럼 한 문서가 여러 거래의 증빙이 될 때, 증빙 목록의 **[복사]**에 거래번호(또는 적립번호)를 쉼표로 여러 개 넣으면 그 거래마다 파일을 **그 거래의 드라이브 폴더에 그 거래 기준 이름**(`재원_증빙종류_금액_YYMMDD`)으로 복사하고 독립된 증빙 항목(비고 "복사: 원본 증빙번호")을 만듭니다. 복사본은 서로 독립이라 한쪽을 지우거나 교체해도 다른 쪽에 영향이 없습니다. API: `POST /api/evidence/{번호}/copy` `{row, targets:[…]}`.

### 증빙 파일 교체 (2026-10-20)

파일을 고쳐 다시 올려야 할 때 증빙 목록의 **[교체]**를 누르고 새 파일을 고르면 같은 증빙번호·증빙종류·비고를 유지한 채 파일만 바뀝니다. 이름은 규칙대로 다시 만들고(확장자가 같으면 같은 이름), 옛 파일은 장부가 새 파일을 가리킨 뒤 드라이브 휴지통으로 보냅니다. API: `POST /api/evidence/{번호}` 에 `row`(또는 `증빙번호`)와 `replace=1`.

### 증빙 항목(실물만)과 첨부 양식

종이 영수증·거래명세서처럼 **실물만 있는 증빙**은 파일 없이 항목을 먼저 만들고, A4 첨부 양식을 출력해 실물을 붙입니다. 파일(스캔·사진)은 나중에 같은 항목에 첨부합니다.

- **증빙번호**: 증빙 1건마다 `{거래번호}-{n}`(예: `2026-공정성-001-3`)이 자동으로 붙습니다. 거래번호별 일련번호로, 시트에 남아 있는 번호 중 최대값 + 1 입니다(2026-10-20: 베타 기간이라 지운 번호를 다시 씁니다. 숨김 `메타` 시트의 `증빙번호최고-…` 키는 더 이상 쓰지 않음). 증빙번호는 고칠 수 없습니다. 증빙번호 열이 없는 이전 장부는 첫 실행 때 증빙 시트 맨 끝에 열을 붙이고 기존 행에 시트 순서대로 거래번호별 번호를 매깁니다(다른 칸은 건드리지 않음).
- **항목 추가 (파일 없이)**: 집행 상세 패널의 '증빙 항목 추가'에서 증빙종류(업로드와 같은 자동완성)와 비고를 넣고 [항목 추가]를 누르면 증빙번호가 붙은 항목이 생깁니다. 드라이브 연결이 없어도 됩니다. 알림의 **[양식 인쇄]** 로 바로 그 항목의 첨부 양식을 엽니다. 목록에는 파일명 자리에 "파일 없음"이 보입니다.
- **파일 첨부**: "파일 없음" 항목의 [파일 첨부]를 누르고 파일 1개를 고르면 그 항목에 올라갑니다. 증빙번호·증빙종류·비고는 그대로이고, 파일 이름·저장 폴더 규칙은 일반 업로드와 같습니다(파일명 날짜는 업로드 폼의 "파일명 날짜"). 이미 파일이 있는 항목에는 다시 첨부할 수 없습니다(새 파일은 [업로드]로 따로 올림).
- **파일 먼저**: 지금처럼 '증빙 업로드'로 파일을 올리면 항목과 파일이 한 번에 생깁니다. 업로드 알림에도 [양식 인쇄]가 있고, 여러 파일을 올렸으면 양식 창에서 [이전]/[다음]으로 넘깁니다.
- **첨부 양식**: 목록의 [양식](모든 항목, 집행 단계와 무관)으로 엽니다. A4 세로 한 장: 위에 3행 표(증빙번호 · 증빙종류 · 금액 / 거래처 · 적요 / 비고), 아래는 실물을 붙이는 빈 칸입니다. 기관명 줄과 쪽 번호는 없습니다. 증빙번호·증빙종류·비고는 증빙 항목에서, 금액·거래처·적요는 집행에서 가져오며 거래처·적요는 한 줄로 줄여 보입니다. [인쇄] 또는 창이 열린 채 Ctrl+P를 누르면 양식만 인쇄됩니다. 창을 열면 초점이 [인쇄]에 있고, Esc는 창을 닫고 누른 버튼으로 돌아갑니다.
- **세는 규칙**: 파일 없는 항목도 증빙입니다. 집행내역의 증빙 수·'증빙 없음' 타일·증빙목록(종류 요약)·결의서 증빙 목록·집행 삭제 차단("증빙을 먼저 지워야")에 모두 포함됩니다. 상세 패널 머리에는 "3개 · 파일 2개"처럼 파일 수를 함께 보여 줍니다. 파일 없는 항목을 지우면 장부의 행만 지워집니다.
- **API**: `POST /api/evidence/{거래번호}/entry` `{증빙종류, 비고}` → 파일 없는 행(증빙번호 부여, 드라이브 호출 없음). `POST /api/evidence/{거래번호}`(multipart `files`, `kind`, `date`, `note`)는 그대로이고, `row`(증빙 시트 행) 또는 `증빙번호`를 함께 보내면 그 파일 없는 항목에 파일 1개를 첨부합니다(응답 `attached: true`, 이미 파일이 있으면 409, 파일이 2개 이상이면 400). `GET /api/evidence/{거래번호}`와 `/api/all`의 증빙 행에는 `증빙번호`와 `has_file`이 들어 있습니다. `DELETE /api/evidence/{row}`는 두 종류 모두 지웁니다(`expect`: `{거래번호, 증빙번호}`).

### 구글 드라이브 OAuth 클라이언트 발급 (최초 1회, 약 10분) <a id="drive"></a>

Google Cloud 콘솔 화면은 2025년부터 "Google 인증 플랫폼(Google Auth Platform)"으로 바뀌었습니다. 아래는 그 기준입니다.

1. <https://console.cloud.google.com/> 에 센터 업무용 구글 계정으로 로그인합니다. 기관 계정이 프로젝트 생성을 막으면 개인 계정을 써도 됩니다(파일은 그 계정의 드라이브에 저장됨).
2. 상단 프로젝트 선택 → **새 프로젝트** (이름 예: `CAIH 회계장부`).
3. 왼쪽 메뉴 **API 및 서비스 → 라이브러리**에서 `Google Drive API`를 찾아 **사용**.
4. 왼쪽 메뉴 **Google 인증 플랫폼 → 시작하기**: 앱 이름과 지원 이메일을 넣고, 대상(Audience)은 **외부**, 연락처 이메일을 넣고 완료합니다.
5. **Google 인증 플랫폼 → 대상**: "테스트 사용자"에 로그인할 구글 계정 이메일을 추가합니다. 추가하지 않으면 로그인 시 `access_denied`(403)가 납니다.
6. **Google 인증 플랫폼 → 클라이언트 → 클라이언트 만들기**: 애플리케이션 유형 **데스크톱 앱**, 이름 아무거나 → 만들기. 생성 직후 뜨는 창에서 **"JSON 다운로드"를 바로 누르세요.** 이 창을 닫으면 다시 받을 수 없고 새로 만들어야 합니다.
7. 앱 오른쪽 위 설정(톱니) → 구글 드라이브 → "OAuth 클라이언트 JSON 업로드"로 그 파일을 올립니다.
8. "드라이브 연결"을 누르면 브라우저에 구글 로그인·동의 화면이 뜹니다. "Google에서 확인하지 않은 앱" 경고가 나오면 테스트 모드에서는 **계속**, 게시 상태에서는 **고급 → 이동**을 누릅니다. 3분 안에 완료하지 않으면 취소됩니다.

**7일 만료 주의.** 앱 게시 상태가 "테스트"이면 구글 정책상 로그인 토큰이 7일마다 만료됩니다. 만료되면 설정 패널에 "인증이 만료되었습니다"가 뜨고 "다시 연결"을 누르면 됩니다. 매주 하는 것이 번거로우면 **Google 인증 플랫폼 → 대상 → 앱 게시(프로덕션으로 푸시)** 를 누르세요. `drive.file`은 민감하지 않은 범위라 구글 심사 없이 게시되고, 이후 토큰이 자동 갱신됩니다. 병원 계정이 Google Workspace라면 대상을 "내부"로 만들면 테스트 사용자·게시 절차가 모두 필요 없습니다.

토큰(`app\google_token.json`)과 클라이언트 JSON(`app\google_client_secret.json`)은 git에 올라가지 않습니다. 다른 PC로 옮길 때는 두 파일을 함께 복사하거나 다시 연결하세요. 드라이브 없이 써 보려면 `.env`에 `LEDGER_DRIVE_MOCK=1`을 넣으면 `app\drive_mock` 로컬 폴더에 저장됩니다.

## 6. 백업과 복구

- 저장할 때마다 저장 직전 파일을 `app\backup\장부명_YYYYMMDD_HHMMSS_*.xlsx`로 복사합니다. **최근 30회분**을 보관합니다(30일이 아니라 30번 저장분이므로 입력이 많은 날은 하루 만에 교체될 수 있음).
- 복구 절차: ① 웹앱 콘솔·Claude Desktop(MCP)·엑셀을 모두 닫는다 → ② `app\backup`에서 원하는 시각의 파일을 고른다(파일 시각 = 그 저장 직전 상태) → ③ 원본 위치(`CAIH_회계장부_2026`)에 복사하고 이름을 `의료인공지능센터_지출장부_2026.xlsx`로 바꾼다 → ④ run.bat 재실행.
- 복원하면 그 이후 입력분과 증빙 기록이 사라집니다. 드라이브의 파일은 그대로 남습니다.
- 주 1회 장부 파일을 공유드라이브 등 다른 곳에 복사해 두기를 권합니다.
- 웹앱과 MCP 서버가 동시에 쓰지 않도록 장부 옆에 `장부명.xlsx.lock` 파일로 잠금을 겁니다. 지워도 됩니다.
- 엑셀에서 장부를 열어 둔 동안은 저장이 막히고 상단에 경고가 뜹니다. 다른 창이나 MCP에서 장부가 바뀐 뒤 수정·삭제하면 "행이 일치하지 않습니다" 오류가 나니 새로고침 후 다시 하세요.
- 수식 셀은 지원하지 않습니다. 금액·날짜 칸에 수식이 있으면 상단에 경고가 뜨고 0으로 집계됩니다.

## 8. MCP 서버 (Claude Desktop / Claude Code 연동)

`mcp_server.py`가 장부를 MCP 도구로 노출합니다. 조회: `list_funds`, `list_tags`, `get_dashboard`, `list_exec`, `get_exec`, `list_req`, `list_budget`, `list_deposit`. 입력: `add_exec`, `add_req`, `add_budget`, `add_deposit`, `update_row`, `delete_row`, `req_to_exec`.

**주의: MCP에는 웹의 제안 카드 같은 확인 단계가 없습니다.** 쓰기 도구는 장부를 바로 바꿉니다. 클라이언트에서 쓰기 도구를 "항상 허용"하지 마세요. 읽기 전용으로만 쓰려면 `.env`에 `LEDGER_MCP_READONLY=1`을 넣으면 쓰기 도구가 등록되지 않습니다. 삭제 후에는 다른 행의 `_row`가 바뀌므로 도구 설명대로 다시 조회해야 하며, `expect_id`(거래번호 등)를 함께 주면 엉뚱한 행을 고치지 않습니다.

Python 실행 파일 경로를 먼저 확인합니다(명령 프롬프트에서 `where python`). 아래의 `python`을 그 절대경로로 바꾸면 안전합니다.

**Claude Code** (모든 폴더에서 쓰려면 `-s user`):

```text
claude mcp add ledger -s user -- python "C:/Users/parkj/Desktop/Project/dev/CAIH_회계장부_2026/app/mcp_server.py"
```

**Claude Desktop**: 설정 → 개발자 → "구성 편집"으로 `%APPDATA%\Claude\claude_desktop_config.json`을 열고 `mcpServers` 안에 아래 항목을 추가합니다(이미 다른 서버가 있으면 쉼표로 이어 붙임). 저장 후 Claude Desktop을 완전히 종료했다가 다시 실행합니다. 같은 내용의 예시 파일이 `app\claude_desktop_config.ledger.json`에 있습니다.

```json
{
  "mcpServers": {
    "ledger": {
      "command": "python",
      "args": ["C:/Users/parkj/Desktop/Project/dev/CAIH_회계장부_2026/app/mcp_server.py"]
    }
  }
}
```

등록 확인: Claude에게 "ledger 의 list_funds 를 실행해 줘"라고 말해 재원 목록이 나오면 됩니다. `run_mcp.bat`은 직접 실행하는 파일이 아닙니다.

집계 규칙: 예산현액 = 재원·예산목별 (이월+당초+변경) 합계. 집행액 = 집행내역 금액 합계(원인발생일 기준, 미승인 건 포함). 품의대기 = 상태 '대기' 품의 합계. 가용잔액 = 예산현액 − 집행액(파일 전체) − 품의대기(날짜 무관). 저장 전 경고도 같은 값을 쓰며(집행내역의 '예산목 잔액' 열은 그 거래까지 원인발생일 순으로 누적한 시점 잔액으로, 예산은 그 거래의 원인발생일까지 신청된 예산변동만 포함하고 품의대기는 빼지 않음. 예산변동의 신청일자는 필수이며, 이전 장부의 빈 값은 앱이 장부 연도의 1월 1일로 채움), 품의→집행 전환과 수정 시에는 해당 행 자신을 빼고 계산합니다. 인건비 선급·미지급은 직전 달까지의 발생액 기준입니다.

집계 범위: 예산 집계(대시보드 칸·표, `/api/all`의 `dashboard.table`, MCP `get_dashboard`, AI 보고서 수치)는 **재원 시트에 있는 재원 × 예산목 11개**만 셉니다. 재원 시트에 없는 재원(외부 인건비 지급처, 엑셀에서 직접 넣은 코드 등)이나 목록 밖 예산목의 집행·대기 품의는 집계하지 않고 `dashboard.excluded` = `{exec: [{거래번호, 원인발생일, 재원, 예산목, 금액, 거래처, 사유, _row}], req: [{품의번호, …}]}` 와 `dashboard.excluded_total` = `{exec, exec_count, req, req_count}`(금액 합계·건수)로 따로 돌려줍니다. 웹 화면의 "집계 제외 n건"(집행내역 빠른 필터 `isExcludedExec`)과 같은 규칙입니다. 월별 추이·거래처·미승인 건수·태그 집계는 이전처럼 전체 집행 기준입니다. 목록 밖 재원의 예산변동 행도 예산현액에 넣지 않습니다.

### API 응답 참고

- **집행 상태**: 시트·API의 저장값 `상태`는 `발생/청구/보완/완료/결의`(완료 = 지출완료일, 결의 = 결의일)이고 화면 이름은 `발생/청구/보완/승인/완료`입니다. 저장값은 바꾸지 않고, `/api/all`·MCP `list_exec`/`get_exec`의 집행 행에 화면 이름 **`상태표시`**를 함께 넣습니다. 대응표는 `/api/meta`와 `/api/all`의 `meta.exec_status_labels`(`{"발생":"발생","청구":"청구","보완":"보완","완료":"승인","결의":"완료"}`). 웹의 집행내역 CSV 상태 열은 화면 이름(상태표시)을 씁니다.
- **연결품의번호**: 집행 행의 `연결품의번호`는 품의→집행 전환(`POST /api/req/{row}/to-exec`, MCP `req_to_exec`)으로만 기록됩니다. 집행 추가·수정·편집 모드 저장에 보낸 값은 무시합니다.

## 10. 자주 묻는 문제

- **"장부 파일을 찾을 수 없습니다"**: 파일이 `app`의 상위 폴더에 정확한 이름으로 있는지, 또는 `.env`의 `LEDGER_XLSX` 경로가 맞는지 확인.
- **저장이 안 되고 "엑셀에서 열려 있음"**: 엑셀을 닫고 다시 저장. 비정상 종료로 `~$` 파일이 남아도 실제로 열려 있지 않으면 저장됩니다.
- **드라이브 연결 버튼이 꺼져 있음**: OAuth JSON을 먼저 올려야 합니다.
- **드라이브 "인증이 만료"**: 테스트 모드 7일 만료. "다시 연결" 또는 앱 게시(5절).
- **AI 오류 "크레딧 부족"**: 제공자 콘솔에서 결제를 확인. "모델을 찾을 수 없음": 설정의 모델명 확인.
- **MCP가 다른 장부를 씀**: `.env`의 `LEDGER_XLSX`는 웹앱과 MCP 모두에 적용됩니다. 두 쪽 모두 재시작하세요. `run_qa.bat`으로 띄운 QA 서버만 QA 장부를 씁니다.

## 재원 종류와 공금 (2026-10-16)

`재원` 시트에 `종류` 열이 있습니다(국책 / 원내 / 위탁 / 교육 / 공금 / 기타). 이전 장부를 열면 열이 맨 끝에 추가되고 비어 있는 재원은 첫 저장 때 **국책**으로 채워집니다(읽을 때도 빈 값은 국책). 재원 폼의 종류 칸에서 바꿉니다. 국책·원내·위탁·교육·기타는 지금처럼 예산목별로 예산·잔액을 관리하고 종류는 표시용입니다.

**공금**은 예산목별 예산 없이 재원 잔액 하나만 관리합니다.
- 입금은 `예산변동` 탭에 적습니다. 공금 재원을 고르면 예산목 칸이 숨고 **입금** 칸(시트의 맨 끝 열 `입금`)만 보입니다. 서버는 공금 행에 예산목 금액이 있거나 입금이 0이면 거부하고, 다른 재원 행에 입금이 있으면 거부합니다. 환입은 음수 입금으로 적습니다.
- 집행·품의·신청의 예산목은 공금에서도 필수입니다(분류용). 잔액 계산에는 쓰지 않습니다.
- 잔액 = 입금 합계 − 집행(전체) − 대기 품의. 대시보드 카드 "재원코드 잔액 (공금)"과 표의 "잔액 (공금)" 한 줄, 집행 폼의 가용잔액 경고, 집행내역의 '예산목 잔액' 열(재원 단위 누적), 지출결의서의 재원 현황("공금 잔액" 한 줄, 합계 줄 없음), API·MCP 대시보드(`예산목: "(공금 잔액)"`)가 모두 이 기준입니다.
- 공금 집행은 예산목별 카드·표에 들어가지 않습니다(집계 제외 목록에도 들어가지 않음).

**잔액 미관리** 체크(재원 폼, 시트 열 `잔액미관리` = Y)는 재원을 출처 표시로만 쓰고 예산·잔액을 관리하지 않을 때 켭니다. 켜면 예산변동을 적을 수 없고(폼 목록에서 빠지고 서버도 거부), 대시보드 카드·표·집계 제외 목록에서 빠지며(머리 안내에 "잔액 미관리 재원 N곳"만 표시), 집행 폼의 가용잔액 경고와 집행내역의 예산목 잔액 열은 비고, 지출결의서 재원 현황은 "예산·잔액을 관리하지 않습니다" 한 줄이 됩니다. 집행·품의·신청 입력은 그대로 됩니다.

## 보완 표시와 보완 이력 (2026-10-18)

집행내역의 청구 단계에서 [보완]을 누르면 **보완 사유**를 묻는 대화상자가 뜨고(필수), 입력해야 상태가 '보완'으로 바뀝니다. [해제]는 처리 내용을 선택으로 받습니다. 표시·해제는 모두 `보완이력` 시트(거래번호 · 일시 · 구분(표시/해제) · 사유)에 한 줄씩 쌓이며, 이전 장부를 열면 시트가 자동으로 추가됩니다. 집행 상세 패널의 '보완 이력' 절에 최신순으로 보이고, 목록의 [해제] 링크에 마우스를 올리면 최근 사유가 보입니다. API: `POST /api/exec/{row}/action` `{action: "fix", extra: {사유}}` / `{action: "unfix", extra: {사유}}`.
