# 센터 회계대장 관리도구 — 사용 안내

`의료인공지능센터_지출장부_2026.xlsx`를 원본으로 쓰는 로컬 웹앱입니다. 엑셀 파일이 곧 데이터베이스이고, 앱은 그 파일을 읽고 씁니다. 엑셀에서도 언제든 열어 볼 수 있습니다.

## 1. 설치 (최초 1회)

필요한 것: Windows PC, Python 3.10 이상, 인터넷(패키지 설치 때만).

1. Python이 없으면 <https://www.python.org/downloads/> 에서 설치합니다. 설치 첫 화면의 **"Add python.exe to PATH"** 를 반드시 체크하세요. 체크하지 않으면 `python`을 입력했을 때 Microsoft Store가 열립니다.
2. 장부 파일 `의료인공지능센터_지출장부_2026.xlsx`가 `app` 폴더의 **바로 위 폴더**(`CAIH_회계장부_2026`)에 있어야 합니다. 다른 위치에 두려면 `.env`에 `LEDGER_XLSX=전체경로`를 적습니다.
3. `app\setup.bat`을 더블클릭합니다. Python 버전을 확인하고 패키지를 설치합니다. 병원망 프록시 때문에 실패하면 화면의 안내대로 `--proxy` 옵션을 씁니다.

## 2. 실행과 종료

- `app\run.bat` 더블클릭 → 콘솔 창이 뜨고 브라우저가 `http://127.0.0.1:8791` 로 열립니다.
- **콘솔 창을 닫으면 앱이 종료됩니다.** 쓰는 동안 최소화해 두세요.
- 이미 실행 중인데 다시 누르면 "이미 실행 중입니다" 안내와 함께 기존 창을 엽니다.
- 포트를 바꾸려면 `.env`에 `LEDGER_PORT=번호`.

**첫 실행 때 장부 구조가 자동으로 보정됩니다.** 재원·적립금·태그·증빙 시트가 추가되고 집행내역에 상태·증빙폴더·증빙목록 열, 품의내역에 상태 열이 생깁니다. 보정 전 파일은 `app\backup`에 백업되고 콘솔에 내용이 표시됩니다. 처음 실행하기 전에 장부 사본을 따로 보관해 두세요. 장부 파일에 차트·이미지·피벗이 있으면 저장 과정(openpyxl)에서 사라질 수 있으니 장부에는 넣지 마세요.

## 3. 처음 시작하기 (순서대로)

1. **재원 탭**에서 과제를 등록합니다. 재원코드는 거래번호(`YYYY-코드-NNN`)에 쓰이므로 짧게, `-` 없이.
2. **예산변동 탭**에서 재원별로 `이월`·`당초` 예산을 넣습니다. 변경은 회차 번호(1, 2, …)로 추가하며 앱이 다음 회차를 제안합니다. 같은 재원의 이월·당초는 한 건만 등록됩니다.
3. **태그 탭**(선택)에 센터 내부 계정을 등록합니다. 등록하면 입력 폼의 태그가 선택식으로 바뀝니다.
4. 우하단 **설정(톱니)** 에서 구글 드라이브를 연결합니다(증빙 업로드에 필요, 4절 참고).
5. AI 도우미는 선택이며 유료입니다(7절).

재원이 없거나 예산을 입력하지 않으면 대시보드 칸과 표에 '예산 미입력'이 표시됩니다. 1~2번을 먼저 하세요.

## 4. 화면 사용법

### 입력 폼 (집행·품의·적립금·예산·재원·태그)

- 필드 순서는 실무 입력 순서입니다: 날짜 → 재원 → 예산목 → 거래처 → 금액 → 적요 → 세목 → 태그 → 부가 정보. 처음 초점은 거래처에 있습니다.
- **Enter**는 다음 칸으로 이동, **Ctrl+Enter**는 저장, **Ctrl+Shift+Enter**(또는 "저장 후 계속" 버튼)는 저장하고 같은 종류의 다음 건을 바로 입력합니다. 이때 재원·예산목·날짜·사용자는 유지되고 거래처·금액·적요는 비워집니다.
- 입력 중 Esc나 취소를 누르면 "버릴까요?"를 묻습니다.
- 필수 항목이 비면 누락 항목을 모두 보여주고 첫 항목에 초점을 둡니다.
- 저장 전에 같은 날·거래처·금액의 건이 있거나, 가용잔액을 넘거나, 금액이 음수이면 확인창이 뜹니다(차단은 아님). 적립금 '사용'도 잔액을 넘으면 확인창이 뜹니다.
- 인건비 확정·적립금 기록·품의 전환으로 생긴 집행은 거래번호 옆에 **인건비 / 적립 / 품의** 배지가 붙고, 누르면 원본 화면으로 이동합니다. 인건비·적립 연결 행은 재원·예산목·금액·거래처·원인발생일이 잠기며(세목·태그·관리번호·날짜·비고만 수정) 삭제는 원본 화면에서만 할 수 있습니다.
- 새 폼의 날짜는 항상 오늘이고, '저장 후 계속'으로 이어 입력할 때만 직전 날짜가 유지됩니다.
- 삭제·확정 취소·청구/완료 처리 뒤 토스트의 **되돌리기**(12초)를 누르면 직전 저장 전 상태로 복구합니다. 그 사이에 다른 창·MCP·엑셀이 장부를 바꿨으면 거부됩니다. 그 뒤에는 app/backup 폴더의 백업 파일로 복원하세요.
- 집행 상세 패널이 열리면 표의 부수 열(날짜 버튼·재원·세목·태그·증빙·비고)을 접어 거래번호·상태·예산목·거래처·적요·금액만 남깁니다.
- 금액에 쉼표를 넣어도 되고, 수식은 안 됩니다.

### 집행내역 탭

- **상태** 열: 발생(원인발생일) → 청구(지급청구일) → 보완(직접 표시) → 승인(지출완료일) → 결의(결의일, 마지막). 날짜가 우선이며 '보완'만 수동입니다. 표에는 원인발생일만 '날짜'로 보이고 나머지 날짜는 행을 클릭한 상세 패널에서 봅니다. 상태 칸 옆의 체크(✓) 버튼이 오늘 날짜로 다음 단계(청구→승인→결의)를 등록하고, 되돌리기와 보완 표시는 상세 패널의 '다음 처리'에서 합니다. 결의를 바로 등록하면 비어 있는 청구일·완료일도 같은 날짜로 채워집니다.
- 표의 버튼: 지급청구일 칸 **[청구일=오늘]**, 지출완료일 칸 **[보완]/[보완해제]**, **[완료일=오늘]**. 완료된 건에는 청구 버튼이 보이지 않습니다. 완료를 취소하려면 행을 클릭해 상세 패널의 **[완료 취소]**.
- 상단 타일(발생·보완·승인·증빙 없음·결의)을 누르면 해당 건만 필터됩니다.
- 적요 칸 아래에 거래처가 작은 글자로 붙고(ref 집행현황 구조), 결제수단 열은 품의와 같은 목록(연구비카드·계좌이체·연구자선지출·공금통장·적립금·기타)을 씁니다. 품의→집행 전환 시 결제수단이 넘어오고, 인건비 확정 집행은 계좌이체, 청구일·완료일·결의일=지급일로 기록됩니다.
- 열 머리글을 누르면 정렬됩니다. 검색은 쉼표를 무시합니다(150,000 = 150000). "상세 열"을 켜면 관리번호·세세목·사용자·비고 열이 보입니다. 작업 열은 오른쪽에 고정되어 가로 스크롤을 해도 보입니다.
- 행을 클릭하면 오른쪽 상세 패널이 열립니다(정보 요약·수정, 다음 처리, 증빙). Esc나 다른 탭으로 이동하면 닫힙니다.
- **CSV** 버튼은 현재 필터의 목록을 파일로 저장합니다.

### 품의내역 탭

품의는 집행 전 계획입니다. **[집행전환]**을 누르면 품의 값이 채워진 집행 입력 폼이 열리고, 저장하는 순간 집행이 생성되며 품의 상태는 `집행완료`로 바뀝니다. 폼을 취소하면 아무것도 바뀌지 않습니다. 전환된 품의는 삭제할 수 없습니다(감사 추적). 품의와 집행은 번호로 연동되지 않고 집행 비고에 `품의 번호`가 남습니다.

### 적립금 탭

거래처별 선결제 잔액을 관리합니다. **적립**을 추가할 때 "집행내역에 기록"을 켜면 집행내역에 선결제 한 건이 생성되어 예산에서 차감되고, 적립 행의 `연결거래번호`에 기록됩니다. **사용**은 잔액만 줄입니다. 연결된 적립 행을 삭제하면 연결 집행도 함께 삭제됩니다(확인창). 태그는 사용 건에 붙입니다.

### 대시보드

- **결의** 탭: 위에서부터 예산목별 가용잔액 칸(큰 숫자 = 예산현액 − 집행 − 품의대기, 막대 = 집행률, 회색은 품의대기; 재원 필터가 '전체'면 합산) → 월별 집행 추이(막대 + 남색 누적선, 예산현액 기준선) · 거래처별 적립금 잔액 → 재원×예산목별 집행 현황 표. 전체 합계(예산현액·집행·집행률·품의대기·가용잔액·미완료)는 필터 줄 오른쪽 한 줄에 나옵니다. 잔액·가용잔액·집행률은 연·월 필터와 무관하게 파일 전체 기준이고(대기 품의도 날짜와 무관하게 전부 차감), 연·월 필터는 **집행액** 열에만 적용됩니다. **월**을 고르면 당월 집행과 연초~당월 누계를 함께 보여줍니다. 재원 목록에 없는 지급처(외부 인건비)나 예산목 밖의 집행은 예산 집계에서 빠지며 필터 줄의 "집계 제외 n건"을 눌러 확인할 수 있습니다.
- **태그** 탭: 집행내역(적립 선결제 건 제외) + 적립금 사용 건을 태그별·분류별·월별로 집계합니다. 결의 집행액과의 차이는 표 위 "조정" 줄에 나옵니다.
- **CSV 저장**, **인쇄** 버튼으로 마감 자료를 뽑습니다.

### 인건비 (상단 **인건비** 버튼, 주소 `/labor`)

회계대장과 분리된 화면에서 직접인건비를 관리합니다. 설계 메모: `docs/인건비_설계_2026-10-13.md`.

- **계획표**: 지급처별 인건비 현황(예산·확정·예정·잔액, 지급월 기준)과 인원×월 배분표(귀속월 기준). 칸을 클릭해 그 달 배분을 편집하고, **기간 일괄 생성**으로 인원·기간·지급처별 월 배분액을 한 번에 만들며, **전월 계획 복사**로 지난달 건을 다음 달 예정으로 복사합니다.
- **지급 원장**: 지급 건 목록. **확정**하면 지급일을 받아 집행내역에 건별 1행(재원 = 지급처, 예산목 = 인원의 내부/외부 구분, 거래처 = 이름)을 자동 추가하고 건을 잠급니다. 수정은 **확정 취소** 후에 하며, 취소·삭제 시 연결 집행도 함께 지워집니다(증빙이 있으면 차단).
- **인원**: 이름·내부/외부 구분·입사일·퇴사일·이월선급, 기준급여(월액·적용 기간), 선급·미지급 현황(이월 + 확정 지급 − 기준급여 발생 + 조정)과 조정 내역.
- **지급처**: 장부 밖 지급처(AI사업단, 연구지원-교수 등)와 인건비예산. 장부 재원은 그대로 지급처로 쓰이며, 인건비 예산은 예산변동의 내부·외부인건비 합계 또는 재원 탭의 **인건비예산** 열(입력 시 우선)입니다. 외부 지급처로 확정한 집행은 집행내역에는 남지만 대시보드 예산 집계에서는 빠집니다.
- 시트: `인원`, `기준급여`, `지급처`, `인건비지급`, `인건비조정` (없으면 자동 생성), `재원` 시트에 `인건비예산` 열 추가.

### 연 단위 운영 (2026-10-13 결정)

장부 파일 하나에 한 해의 데이터만 둡니다. 해가 바뀌면 새 파일을 만들고 `.env`의 `LEDGER_XLSX`를 바꿉니다. 재원·태그·인원·지급처 같은 기준정보는 새 파일에 다시 등록(또는 시트 복사)하고, 예산변동의 '이월' 회차와 인원의 '이월선급'에 전년도 잔액을 넣습니다. 대시보드·인건비의 연도 필터는 같은 파일 안의 연도 구분용이며, 파일을 연도별로 나누면 예산(전 기간 합계)과 집행(연도 필터)의 기준 차이가 생기지 않습니다.

## 5. 증빙 관리 (구글 드라이브)

집행 행의 상세 패널에서 증빙 파일을 올리고 지웁니다.

- 저장 위치: 내 드라이브 / 증빙관리 / YYYY / 재원코드 / 거래번호 / (첫 업로드 때 자동 생성)
- 파일명: `재원_적요_증빙종류_금액_YYMMDD.ext` (같은 이름이 있으면 `_2`, `_3`). 날짜는 업로드 폼의 "파일명 날짜"(기본값 원인발생일)
- 장부 기록: `증빙` 시트와 집행내역의 `증빙폴더`(폴더 링크), `증빙목록`(종류 요약) 열
- 삭제하면 장부에서 지우고 드라이브 파일은 휴지통으로 보냅니다(30일 뒤 영구 삭제). 여러 파일을 올리다 중간에 실패하면 그 요청에서 올린 파일은 모두 되돌립니다.
- 증빙종류는 자유 입력이며 이전 값이 자동완성됩니다.
- 앱은 자기가 만든 파일만 접근합니다(`drive.file`). 드라이브에서 '증빙관리' 폴더를 옮기거나 지우지 마세요.

### 구글 드라이브 OAuth 클라이언트 발급 (최초 1회, 약 10분) <a id="drive"></a>

Google Cloud 콘솔 화면은 2025년부터 "Google 인증 플랫폼(Google Auth Platform)"으로 바뀌었습니다. 아래는 그 기준입니다.

1. <https://console.cloud.google.com/> 에 센터 업무용 구글 계정으로 로그인합니다. 기관 계정이 프로젝트 생성을 막으면 개인 계정을 써도 됩니다(파일은 그 계정의 드라이브에 저장됨).
2. 상단 프로젝트 선택 → **새 프로젝트** (이름 예: `CAIH 회계장부`).
3. 왼쪽 메뉴 **API 및 서비스 → 라이브러리**에서 `Google Drive API`를 찾아 **사용**.
4. 왼쪽 메뉴 **Google 인증 플랫폼 → 시작하기**: 앱 이름과 지원 이메일을 넣고, 대상(Audience)은 **외부**, 연락처 이메일을 넣고 완료합니다.
5. **Google 인증 플랫폼 → 대상**: "테스트 사용자"에 로그인할 구글 계정 이메일을 추가합니다. 추가하지 않으면 로그인 시 `access_denied`(403)가 납니다.
6. **Google 인증 플랫폼 → 클라이언트 → 클라이언트 만들기**: 애플리케이션 유형 **데스크톱 앱**, 이름 아무거나 → 만들기. 생성 직후 뜨는 창에서 **"JSON 다운로드"를 바로 누르세요.** 이 창을 닫으면 다시 받을 수 없고 새로 만들어야 합니다.
7. 앱 우하단 설정 → 구글 드라이브 → "OAuth 클라이언트 JSON 업로드"로 그 파일을 올립니다.
8. "드라이브 연결"을 누르면 브라우저에 구글 로그인·동의 화면이 뜹니다. "Google에서 확인하지 않은 앱" 경고가 나오면 테스트 모드에서는 **계속**, 게시 상태에서는 **고급 → 이동**을 누릅니다. 3분 안에 완료하지 않으면 취소됩니다.

**7일 만료 주의.** 앱 게시 상태가 "테스트"이면 구글 정책상 로그인 토큰이 7일마다 만료됩니다. 만료되면 설정 패널에 "인증이 만료되었습니다"가 뜨고 "다시 연결"을 누르면 됩니다. 매주 하는 것이 번거로우면 **Google 인증 플랫폼 → 대상 → 앱 게시(프로덕션으로 푸시)** 를 누르세요. `drive.file`은 민감하지 않은 범위라 구글 심사 없이 게시되고, 이후 토큰이 자동 갱신됩니다. 병원 계정이 Google Workspace라면 대상을 "내부"로 만들면 테스트 사용자·게시 절차가 모두 필요 없습니다.

토큰(`app\google_token.json`)과 클라이언트 JSON(`app\google_client_secret.json`)은 git에 올라가지 않습니다. 다른 PC로 옮길 때는 두 파일을 함께 복사하거나 다시 연결하세요. 드라이브 없이 써 보려면 `.env`에 `LEDGER_DRIVE_MOCK=1`을 넣으면 `app\drive_mock` 로컬 폴더에 저장됩니다.

## 6. 백업과 복구

- 저장할 때마다 저장 직전 파일을 `app\backup\장부명_YYYYMMDD_HHMMSS_*.xlsx`로 복사합니다. **최근 30회분**을 보관합니다(30일이 아니라 30번 저장분이므로 입력이 많은 날은 하루 만에 교체될 수 있음).
- 복구 절차: ① 웹앱 콘솔·Claude Desktop(MCP)·엑셀을 모두 닫는다 → ② `app\backup`에서 원하는 시각의 파일을 고른다(파일 시각 = 그 저장 직전 상태) → ③ 원본 위치(`CAIH_회계장부_2026`)에 복사하고 이름을 `의료인공지능센터_지출장부_2026.xlsx`로 바꾼다 → ④ run.bat 재실행.
- 복원하면 그 이후 입력분과 증빙 기록이 사라집니다. 드라이브의 파일은 그대로 남습니다.
- 주 1회 장부 파일을 공유드라이브 등 다른 곳에 복사해 두기를 권합니다.
- 웹앱과 MCP 서버가 동시에 쓰지 않도록 장부 옆에 `장부명.xlsx.lock` 파일로 잠금을 겁니다. 지워도 됩니다.
- 엑셀에서 장부를 열어 둔 동안은 저장이 막히고 상단에 경고가 뜹니다. 다른 창이나 MCP에서 장부가 바뀐 뒤 수정·삭제하면 "행이 일치하지 않습니다" 오류가 나니 새로고침 후 다시 하세요.
- 수식 셀은 지원하지 않습니다. 금액·날짜 칸에 수식이 있으면 상단에 경고가 뜨고 0으로 집계됩니다.

## 7. AI 도우미 (선택 · 유료)

상단 우측 설정 → AI 도우미에서 제공자(Anthropic 또는 OpenAI 호환)·모델·API 키를 넣고 "연결 확인 후 저장"을 누릅니다. 키가 없으면 AI 버튼이 비활성으로 보입니다. **질문마다 장부 전체(거래처·사용자 이름 포함)가 선택한 AI 서버로 전송되며 사용량에 따라 과금됩니다.**

| 기능 | 위치 | 동작 |
|---|---|---|
| 장부 Q&A · 입력 제안 | 상단 "AI 도우미" → 우측 패널 | 장부를 근거로 답합니다. "5/20 ABC식당 회의비 85,000원 집행 기록해줘"처럼 말하면 **제안 카드**가 뜨고, "검토 후 저장"을 누르면 입력 폼이 채워진 채 열립니다. 저장은 사용자가 직접 하며 AI는 장부를 바꾸지 못합니다. 기존 행 수정·품의→집행 전환도 같은 방식입니다. |
| 영수증 추출 | 집행/품의 입력 폼 "영수증에서 채우기" | 이미지·PDF에서 일자·거래처·금액·적요·세목·예산목을 읽어 **빈 칸만** 채우고 노란색으로 표시합니다. 재원·태그·사용자는 직접 고르고, 금액은 부가세 포함 합계입니다. |
| 추천·검증 | 집행/품의 입력 폼 "AI 추천·검증" | 거래처 이력과 예산 현황으로 예산목·세목·태그를 추천하고 중복·잔액 초과를 경고합니다. |
| 보고서 초안 | AI 도우미 패널 상단 "보고서 초안 생성" (재원·연도·월·종류 선택) | 서버가 집계한 수치를 모델에 넘겨 서술만 맡깁니다. 그래도 수치는 대시보드 표와 대조하세요. |

- Anthropic 기본 모델은 `claude-sonnet-5-5`, 응답 품질은 "보통(medium)"입니다. 서버 측 폴백(거부 시 재시도)과 1시간 프롬프트 캐시는 Anthropic 경로에만 적용됩니다.
- OpenAI 호환 경로(Base URL 지정 시 Ollama·vLLM·LM Studio 가능)는 모델이 도구 호출과 JSON 스키마 출력을 지원해야 제안·영수증·추천이 동작합니다. "연결 확인"이 도구 호출 지원 여부도 알려줍니다. 영수증 PDF는 OpenAI 공식 API에서만 됩니다.

## 8. MCP 서버 (Claude Desktop / Claude Code 연동)

`mcp_server.py`가 장부를 MCP 도구로 노출합니다. 조회: `list_funds`, `list_tags`, `get_dashboard`, `list_exec`, `get_exec`, `list_req`, `list_budget`, `list_deposit`. 입력: `add_exec`, `add_req`, `add_budget`, `add_deposit`, `update_row`, `delete_row`, `req_to_exec`.

**주의: MCP에는 웹의 제안 카드 같은 확인 단계가 없습니다.** 쓰기 도구는 장부를 바로 바꿉니다. 클라이언트에서 쓰기 도구를 "항상 허용"하지 마세요. 읽기 전용으로만 쓰려면 `.env`에 `LEDGER_MCP_READONLY=1`을 넣으면 쓰기 도구가 등록되지 않습니다. 삭제 후에는 다른 행의 `_row`가 바뀌므로 도구 설명대로 다시 조회해야 하며, `expect_id`(거래번호 등)를 함께 주면 엉뚱한 행을 고치지 않습니다.

Python 실행 파일 경로를 먼저 확인합니다(명령 프롬프트에서 `where python`). 아래의 `python`을 그 절대경로로 바꾸면 안전합니다.

**Claude Code** (모든 폴더에서 쓰려면 `-s user`):

```text
claude mcp add ledger -s user -- python "C:/Users/parkj/Desktop/Project/01 in progress/CAIH_회계장부_2026/app/mcp_server.py"
```

**Claude Desktop**: 설정 → 개발자 → "구성 편집"으로 `%APPDATA%\Claude\claude_desktop_config.json`을 열고 `mcpServers` 안에 아래 항목을 추가합니다(이미 다른 서버가 있으면 쉼표로 이어 붙임). 저장 후 Claude Desktop을 완전히 종료했다가 다시 실행합니다. 같은 내용의 예시 파일이 `app\claude_desktop_config.ledger.json`에 있습니다.

```json
{
  "mcpServers": {
    "ledger": {
      "command": "python",
      "args": ["C:/Users/parkj/Desktop/Project/01 in progress/CAIH_회계장부_2026/app/mcp_server.py"]
    }
  }
}
```

등록 확인: Claude에게 "ledger 의 list_funds 를 실행해 줘"라고 말해 재원 목록이 나오면 됩니다. `run_mcp.bat`은 직접 실행하는 파일이 아닙니다.

## 9. 시트 구조 요약

| 시트 | 내용 |
|---|---|
| 재원 | 앱이 신설. 재원코드·과제명·시작일·종료일·비고 |
| 예산변동 | 8행 헤더 아래 변동 이력. 변경회차 `이월`/`당초`/숫자. 1~7행 요약은 앱이 전체 합계로 갱신 |
| 집행내역 | 기존 15열 + 상태·증빙폴더·증빙목록. 거래번호 `YYYY-재원코드-NNN` 자동 부여 |
| 품의내역 | 기존 14열 + 상태(대기/집행완료/취소) |
| 적립금 | 앱이 신설. 거래처별 적립/사용, 연결거래번호, 태그 |
| 태그 | 앱이 신설. 태그명·분류·설명 (센터 내부 계정) |
| 증빙 | 앱이 신설. 집행 건별 증빙 파일 기록 (드라이브 파일 ID 포함) |
| 대시보드 | 사용하지 않음 (대시보드는 웹에서만) |

집계 규칙: 예산현액 = 재원·예산목별 (이월+당초+변경) 합계. 집행액 = 집행내역 금액 합계(원인발생일 기준, 미완료 건 포함). 품의대기 = 상태 '대기' 품의 합계. 가용잔액 = 예산현액 − 집행액(파일 전체) − 품의대기(날짜 무관). 집행내역의 '예산목 잔액' 열과 저장 전 경고도 같은 값을 쓰며, 품의→집행 전환과 수정 시에는 해당 행 자신을 빼고 계산합니다. 인건비 선급·미지급은 직전 달까지의 발생액 기준입니다.

## 10. 자주 묻는 문제

- **"장부 파일을 찾을 수 없습니다"**: 파일이 `app`의 상위 폴더에 정확한 이름으로 있는지, 또는 `.env`의 `LEDGER_XLSX` 경로가 맞는지 확인.
- **저장이 안 되고 "엑셀에서 열려 있음"**: 엑셀을 닫고 다시 저장. 비정상 종료로 `~$` 파일이 남아도 실제로 열려 있지 않으면 저장됩니다.
- **드라이브 연결 버튼이 꺼져 있음**: OAuth JSON을 먼저 올려야 합니다.
- **드라이브 "인증이 만료"**: 테스트 모드 7일 만료. "다시 연결" 또는 앱 게시(5절).
- **AI 오류 "크레딧 부족"**: 제공자 콘솔에서 결제를 확인. "모델을 찾을 수 없음": 설정의 모델명 확인.
- **MCP가 다른 장부를 씀**: `.env`의 `LEDGER_XLSX`는 웹앱과 MCP 모두에 적용됩니다. 두 쪽 모두 재시작하세요.
