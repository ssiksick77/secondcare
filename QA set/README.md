# QA팀 전달 패키지

대상: CAIH 회계장부 / 데이터셋: `QA26JANSEP_V1` / 작성일: 2026-10-14

이 폴더는 `app`과 같은 위계에 있는 QA 전달용 사본이다. 원래의 설계·데이터 파일은 `docs`에 보존했다. 실제 기존 장부 백업, `.env`, 인증·토큰 파일, 데이터 설치 스크립트, 임시 백업은 포함하지 않았다.

## 시작 순서

1. [QA 기본 체크리스트](QA_기본체크리스트_2026-10-14.md)에서 범위·기대 결과·확인 필요 사항을 읽는다. 38개 항목의 상태는 모두 **미실행**이고 실제 결과 칸은 빈칸이다.
2. [데이터 납품 보고서](데이터_납품보고서.md)에서 데이터 구조·건수·가정·체크리스트 연결표·예상 합계·복원 절차를 확인한다.
3. [전체 거래 검토표](거래내역_검토표.md)와 [기록 식별자](record_ids.json)로 필요한 시나리오를 찾는다.
4. 변경 테스트는 격리된 테스트 환경에서 실행한다. 필요하면 앱·MCP·엑셀을 종료하고 [초기 가상 장부](synthetic_baseline.xlsx)를 해당 테스트 환경의 장부 경로에 복사해 초기화한다. 다른 환경의 운영 장부를 덮어쓰지 않는다.
5. 오류·경고 사례는 개별 사전 조건을 확인한 뒤 하나씩 실행하고 결과를 기록한다. JSON 파일은 UI 가져오기 파일이 아니라 입력값·API 요청 검토 자료다.

## 전달 시 알아둘 사항

- 모든 업무 데이터는 가상이다. 147건은 **집행내역** 건수이며 품의·신청·주문 등을 중복 합산한 숫자가 아니다.
- 원래 작업 환경에서는 실제 장부 백업 후 앱 API를 이용해 가상 장부를 반영했다. 이 폴더를 다른 PC에 복사하는 것만으로 그 PC의 앱에 입력되지는 않는다.
- `installed.json`과 납품 보고서의 절대 경로는 원래 작업 PC의 이력이다. 다른 PC에서는 실제 앱의 `LEDGER_XLSX` 설정을 확인한다. 기존 실제 데이터 백업과 설정 백업은 이 패키지에 없다.
- 체크리스트·보고서의 `../app/` 링크는 프로젝트 안에서 열면 연결된다. 이 폴더만 전달하는 경우 해당 앱 소스·사용 안내는 별도로 제공해야 한다.
- **데이터 생성·입력 검증과 정식 QA 결과는 다르다.** 브라우저 렌더링·조작·인쇄, 외부 Drive·AI 기능, 기관별 승인 권한·여비 규칙은 검증 완료로 취급하지 않는다.
- 현재 소스의 집행 상태명과 기존 문서의 상태명 차이는 납품 보고서에 기록되어 있다. 합격 기준 확정 후 실행한다.
- 오류·경고 데이터는 기본 장부와 분리했다. 정상 장부에 일괄로 섞어 넣지 않는다.
