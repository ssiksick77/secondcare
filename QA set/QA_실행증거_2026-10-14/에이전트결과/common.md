## 4. 발견 사항

심각도: P0 = 데이터 손실·오기록 직결, P1 = 업무 오류 가능성 높음, P2 = 경미·개선. 이번 범위에서 P0 결함은 확인되지 않았다.

### [결함] F-02 (P1) 일반 [집행 추가]가 직전 재원·예산목을 미리 채우고 현재 필터 재원을 무시
- 관련 기능: 입력 폼 기본값 (`app.js` `openForm`: `defaults = {재원: FILTERS.exec.재원, …, ...lastDefaults(kind)}`)
- 재현: 집행 1건 저장(QA10) → 집행내역 재원 필터를 QA05로 변경 → [집행 추가].
- 기대·근거: R1 4절은 재원·예산목·날짜·사용자 유지를 "저장 후 계속"에 한해 설명한다("새 폼의 날짜는 항상 오늘"). 필터 재원이 기본값이어야 한다(QA 제안).
- 실제: 재원 QA10·예산목 연구재료비·사용자 Alex가 미리 채워진다. 이 값은 같은 탭이 열려 있는 동안 sessionStorage로 유지된다.
- 업무 영향: 재원 8~10개를 번갈아 입력하는 Alex가 QA05를 보면서 추가하면 QA10에 잘못 저장될 수 있다. 재원 간 집행 오귀속은 정산 오류로 이어진다.
- 증거: `shots\common_C-14_new_form_after_filter_QA05.png`, `work_common\c14.out` 마지막 줄.

- 실제: 화면은 `=12000*3+500`을 36500으로 바꿔 저장한다. API·MCP 경로는 같은 문자열을 400으로 거부한다. R1 4절에 지원 설명과 "수식은 안 됩니다"가 함께 있다.
- 필요 조치: 명세 정리. 금액 칸 계산식은 화면 전용 기능이고 엑셀 수식 셀은 미지원이라는 점을 구분해 적어야 한다.
- 증거: `c02_ui.out`, C-02 API 출력.

### [결함] F-06 (P2) 금액 계산식·숫자 해석이 명세보다 넓음
- 실제: `=2**10`이 1024로 저장된다(R1 "사칙연산과 괄호만"과 다름). `=10/3`은 안내 없이 3으로 반올림된다. `1,2,3`은 123으로 받아들여진다. 집행 금액 1.5원도 저장된다(화면·API 모두).
- 업무 영향: 오타가 그대로 금액이 된다. 원 단위 미만 금액이 장부에 남는다.
- 증거: `c02_ui.out`, alex.py 금액 오타 출력.

### [결함] F-07 (P2) 신청 단가에 소수가 허용됨
- 재현: POST /api/request 장비, 단가 0.5 또는 1000.7.
- 기대·근거: R1 신청 검증의 "단가는 0보다 크고 1조 원 이하". 서버 오류 문구도 "0보다 큰 원 단위 금액"이다.
- 실제: 200. 단가·금액이 0.5와 1000.7로 저장된다(R-2026-022, -023).
- 증거: C-03 출력.

### [결함] F-08 (P2) 매우 큰 정수 단가에 500 서버 오류
- 재현: POST /api/request `{"구분":"장비", …, "단가": 10**400}`(JSON 정수 리터럴).
- 기대: 400과 '단가' 필드 오류(R1 "금액·부가세액은 유한한 숫자, 오류 문구는 실제 열 이름").
- 실제: 500 `서버 오류: int too large to convert to float`(`store._to_num`의 `math.isfinite`에서 OverflowError). 저장은 되지 않는다.
- 증거: C-03 출력, `inst_common\server.log`.

### [사용성 개선 제안] F-09 (P2) 서버 검증 오류가 필드에 연결되지 않음
- 실제: 서버가 거부한 오류(예: 금액 0)는 폼 상단 문구로만 나온다. 필드 강조(aria-invalid)와 초점 이동이 없다. 클라이언트 오류 문구에는 앞에 `/ `가 붙는다("`/ 확인 필요: 금액(숫자 아님)`").
- 증거: `shots\common_ALEX_server_error_field.png`, `common_C-02_ui_abc.png`.

### [확인 필요] F-10 (P2) /api/undo를 write_id 없이 부르면 다른 사람의 직전 저장도 되돌림
- 재현: 집행 삭제(API) → 다른 건 저장 → `POST /api/undo {}`.
- 실제: 200. 다른 건의 저장이 취소된다. write_id를 넣으면 올바르게 거부된다. 화면은 `LAST_WRITE_ID`가 비어 있으면 빈 값을 보낼 수 있는 구조다.
- 근거: R1 "그 사이에 다른 창·MCP·엑셀이 장부를 바꿨으면 거부됩니다". 현재는 write_id를 보낼 때만 보장된다.
- 증거: `c09.out` 마지막 줄.

### [확인 필요] F-11 (P2) expect 없는 PUT은 충돌 검사 없이 덮어씀
- 실제: 구형 본문(레코드 자체)이나 `expect: {거래번호}`만 보낸 PUT은 다른 창의 변경을 덮어쓴다(200). 화면은 항상 `_snapshot`을 보내므로 UI 경로는 안전하다. MCP·외부 호출의 기준은 확인이 필요하다.
- 증거: C-08 API 출력.

### [결함] F-12 (P2) 서버가 등록되지 않은 재원 코드와 범위 밖 날짜를 받아들임. 집행 거래처·적요는 필수가 아님
- 실제: 재원 `QA99`(재원 시트에 없음)로 집행이 저장되고 대시보드에 새 재원으로 나타난다. 1900-01-01·2099-12-31 집행도 저장된다. 재원 기간(종료 2026-09-30) 밖 날짜에 경고가 없다. 거래처·적요 없는 집행이 저장된다.
- 근거: 기관 규칙이 없어 기간 밖 집행 허용 여부는 확인 필요. 존재하지 않는 재원 코드 거부는 QA 제안. 화면은 select라 직접 입력은 어렵지만, 편집 모드 붙여넣기·API·MCP 경로가 있다.
- 증거: `alex.out` A5·A6, C-01 API 출력.

### [사용성 개선 제안] F-13 (P2) 편집 모드 일괄 저장이 첫 오류 한 건만 알려 줌

### [사용성 개선 제안] F-14 (P2) 금액 해석 기준이 화면과 API에서 다름

### [사용성 개선 제안] F-15 (P2) 금액 검색이 부분 일치이고 필터 일괄 초기화 버튼이 없음
