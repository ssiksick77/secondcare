## 1. 사용자 배경과 설계 원칙

Alex는 비영리 국립병원 산하 소형 연구실의 연구비 관리 담당자이며, 연간 약 8~10개 재원의 예산·지출 업무 대부분을 담당한다. Alex의 승인 권한, 재원별 집행 기준, 기관 내부 규정은 별도 제공된 내용만 사실로 취급한다. 환자 정보 취급이나 특정 법규·회계 기준 적용은 가정하지 않는다.

기대 결과는 명시된 요구사항 또는 별도로 표시한 QA 제안에 근거한다. 현재 구현을 그대로 정답으로 취급하지 않는다. 문서 충돌이나 근거 부족이 있는 기준은 확인 필요로 표시한다. 미구현·범위 밖 기능은 필수 통과 대상에서 제외하며, 기능 부재만으로 결함으로 판정하지 않는다.

## 2. MVP 탐색 요약

### 2.1 확인 범위와 한계

연결된 브라우저가 없어 실제 화면 클릭 탐색은 완료하지 못했다. 화면 소스·서버 코드를 검토하고, 앱을 프로세스 내부에서 호출하여 조회 경로와 현재 데이터를 확인했다. 아래의 HTTP 응답 관찰은 브라우저 렌더링이나 사용자 흐름의 성공을 의미하지 않는다.

| 구분 | 확인 내용 |
|---|---|
| 프로그램 형태 | FastAPI 기반 로컬 웹앱. 엑셀 파일을 데이터 원본으로 사용 |
| 실행 안내 | `app/run.bat`, 기본 주소 `http://127.0.0.1:8791` |
| 조회 탐색 | `/`, `/labor`, `/request`, `/api/meta`, `/api/all`을 앱 내부 테스트 클라이언트로 호출해 HTTP 200 응답 확인 |
| 현재 데이터 | 재원 1개, 예산변동 2건, 집행 34건, 적립금 1건, 태그 2개, 인원 5명, 인건비 지급 14건 |
| 빈 영역 | 품의·증빙·기준급여·외부 지급처·인건비 조정·신청·주문·신청첨부 각각 0건 |
| 데이터 보호 | 생성·수정·삭제·확정·승인·업로드 미수행. 마지막 조회 전후 원본 엑셀 SHA-256 일치 |
| 미확인 영역 | 실제 화면 표시·클릭·키보드 조작, 입력·저장 결과, 출력물, Drive·AI 연결, 8~10개 재원 환경 |
| 탐색 시 주의점 | 일반 실행 경로에는 장부 구조를 자동 보정하고 저장하는 과정이 있음. 이번에는 해당 초기화 경로를 실행하지 않음 |

## 3. QA 체크리스트

### 3.1 적용 기준과 공통 사전 조건

- **명세 기준**: R1·R2에 명시된 기대 결과. 문서 간 충돌이 있으면 확정 보류.
- **QA 제안**: 문서만으로 확정되지 않은 안전성·사용성 기준. 담당자 합의 후 합격 기준으로 사용.
- 모든 변경 시나리오는 **원본과 분리된 테스트 장부 및 변경 허용**을 공통 사전 조건으로 한다.
- Drive·AI는 별도의 테스트 연결과 사용 범위를 확인한 뒤 실행한다.
- 실행 상태와 실제 결과·증거·연결된 결함 ID 칸은 자동 실행 결과로 기입한다(머리말 실행 기록 참고). 미실행은 사유를 함께 적는다.
- 기능·기준 확정 후 적용 여부를 검토한다. 확인 필요 항목을 임의의 기준으로 통과·실패 처리하지 않는다.

| 우선순위 | 정의 |
|---|---|
| P0 | 금액·데이터·권한의 중대한 오류 또는 핵심 업무 중단 위험 |
| P1 | 주요 업무의 정확성과 완료 가능성 |
| P2 | 사용 편의와 기타 낮은 영향의 문제 |

테스트 데이터는 실제 개인정보 대신 가상 데이터로 준비한다. 재원은 `F01~F10`을 사용하고, 유사 과제명 2개와 거래 없는 재원 1개를 포함한다. 금액 예시는 원 단위이며, 각 시나리오는 별도 초기 상태에서 수행하여 다른 항목의 기록이 합계에 섞이지 않게 한다.

## 5. 실행 기록 작성 방법

실제 QA 실행 시 각 항목의 환경·앱 버전 또는 커밋·테스트 장부 식별자·실행자를 함께 남긴다. 기대 결과의 확인 필요 사항을 먼저 확정하고, 수행 후에만 실행 상태와 실제 결과를 작성한다. 실패 시 재현 단계와 증거 위치, 연결된 결함 ID를 기록한다. 환경·데이터 부족으로 실행하지 못한 항목은 실패로 판정하지 않고 미실행 사유를 기록한다.

이번 문서의 조회 관찰과 소스 검토는 체크리스트 설계를 위한 근거이며, 체크리스트의 통과·실패 결과는 아직 없다.
