# 센터 회계대장 관리도구 — 사용자 관점 전면 리뷰 (2026-10-13)

리뷰 방식: 5개 에이전트(Fable·Opus×2·Sonnet·Haiku)가 각각 다른 사용자 역할로 복사본 장부에 앱을 띄워 직접 조작·코드 분석. Fable(본 세션)이 중복을 합치고 상위 지적을 코드로 재검증해 우선순위를 매김. 원본 장부·프로젝트 파일은 수정하지 않음.

역할 분담: Fable=월간 업무 흐름 전체, Opus1=설치·설정·문서(온보딩), Opus2=일상 입력 효율·표 조작, Sonnet=AI·MCP, Haiku=대시보드·증빙·문구.

범례: ✔ = Fable이 코드/재현으로 확인한 버그, ◇ = 코드 근거가 분명한 결함(재현은 안 함), ○ = 개선 제안.

## B. 효과 큰 개선 (실무 효율)

- **B1 연속 입력**: 저장 후 "계속 입력" 버튼, 직전 재원·예산목·날짜·사용자 기억, 토스트에 저장된 거래번호 표시. (Opus2·Fable 공통)
- **B2 폼 순서·초점**: 원인발생일→재원→예산목→거래처→금액→적요→세목→태그, 관리번호·세세목·비고는 뒤로. 첫 초점은 선택 항목인 관리번호가 아니라 거래처/날짜. 날짜 칸은 Tab 4번 필요 → 텍스트 입력(1013, 10/13) 허용 검토.
- **B3 Enter/Esc**: 텍스트 칸 Enter는 다음 칸, 저장은 Ctrl+Enter. 값이 바뀐 채 Esc/취소 시 "버릴까요?" 확인.
- **B4 표 조작성**: 작업 열 우측 고정(sticky), 관리번호·세세목·비고 열 접기, 머리글 정렬, 검색 시 쉼표 무시(150,000), 긴 적요 말줄임+툴팁, 1280~1366px에서 가로 스크롤 힌트. 드로어가 표/대시보드를 가림 → 탭 전환·Esc 시 닫기, 열릴 때 본문 여백.
- **B5 단계 버튼·용어**: "발생/미청구/지급대기"가 혼용됨. 상태명 통일(미청구·청구중·보완필요·완료), 버튼 라벨 "청구일=오늘", 완료 행은 버튼 숨김, 토스트에 [되돌리기] 5초.
- **B6 품의→집행 전환**: 전환 후 "수정 폼"이 또 열려 2단계처럼 보이고 취소해도 전환은 유지됨. 전환 전 한 번의 대화상자에서 관리번호·청구일을 받아 원자적으로 처리(API `extra` 이미 지원), 전환 후 필터 해제·새 행 하이라이트.
- **B7 월 마감 수단**: 대시보드 월(기간) 필터 + 당월/누계 열, 표 CSV/클립보드 복사, 인쇄 보기. 현재는 AI 보고서 외에 마감 자료를 뽑을 방법이 없음.
- **B8 저장 전 경고**: 가용잔액 초과 시 확인창(차단 아님), 같은 날·거래처·금액 중복 경고, 음수 금액 확인. 수정으로 재원/연도를 바꾸면 거래번호가 어긋남 → 경고.
- **B9 폼 검증 메시지**: 누락 항목 전부 나열 + 첫 오류 칸 포커스, 예산목 오류에 허용 목록 표시.
- **B10 대시보드 설명**: 카드 아래 "집행률 = 집행액 ÷ 예산현액" 정의, 연도 선택 시 "예산은 전 기간 기준" 명시, 태그 탭 합계와 결의 집행액의 차이(선결제 제외·적립금 사용 포함) 조정 줄, 차트 막대 값·단위 표시, 범례는 데이터 있는 재원만.
- **B11 적립 폼**: "집행내역에 기록" 시 태그 칸이 둘(`태그`, `_태그`)이고 `_태그` 힌트 "기본값 적립금"과 실제 기본값(빈 값) 불일치 → 선택식으로 통일.
- **B12 삭제 확인창**: 번호만 보여줌 → 거래처·금액·날짜 포함, 기본 초점을 "취소"에.
- **B13 저장 체감**: 3,000건에서 저장 1~1.8초(측정). "저장 중…" 표시, 응답 레코드만 반영해 전체 재조회 생략, 백업은 일별 첫 저장 별도 보존.

## C. 온보딩·문서·설정

- C1 README에 전제조건 추가: Python 3.10+ (코드가 `dict | None` 사용), PATH 체크, `python -m pip`, app 폴더에서 실행, 장부 파일 위치 규칙. `setup.bat` 제공 또는 run.bat에서 패키지 미설치 감지.
- C2 첫 실행 시 원본 장부가 안내 없이 수정됨(시트 4개·열 5개 추가, 예산변동 8행 헤더 덮어씀). 콘솔에 보정 내용·백업 경로 출력, README에 "첫 실행 전 사본 보관".
- C3 "처음 시작하기" 체크리스트(재원→예산→태그→드라이브→AI). 재원이 없을 때 대시보드 빈 상태 안내(현재는 가용잔액이 음수 빨간색으로 보여 오류처럼 보임).
- C4 OAuth 절차를 현재 Google Auth Platform 화면(개요/브랜딩/대상/클라이언트) 기준으로 재작성. 클라이언트 JSON은 생성 직후에만 다운로드 가능, 테스트 사용자 미등록 시 403, 7일 만료 → 앱 게시 권장(drive.file은 심사 불필요), Workspace 계정이면 "내부" 유형.
- C5 백업 복구 절차를 단계로(프로그램 종료→backup 파일 선택→원본 위치에 복사·이름 변경→재시작). 30개는 30회분임을 명시, 주 1회 외부 사본 권장.
- C6 MCP 등록: Claude Desktop 설정 파일 위치, 기존 항목과 합치기, 재시작, `python` 절대경로, Claude Code `-s user` 범위, 동작 확인 문장("list_funds 해 줘"). run_mcp.bat 용도 주석.
- C7 설정 패널: 섹션 순서를 "드라이브(증빙 필수) → AI(선택·유료)"로, 하단 "저장"이 AI 설정만 저장함을 표시, 키 미설정 시 placeholder를 "sk-ant-… 붙여넣기"로, 발급처 링크·과금 고지, effort를 "빠름/보통/정확"으로. AI 키 없을 때 AI 버튼을 숨기지 말고 비활성+안내. "저장 후 연결 확인"은 성공 시에만 저장.
- C8 requirements 버전 고정(특히 `mcp` 2.x), 포트 중복 실행 시 "이미 실행 중" 안내, 콘솔 창 닫으면 종료됨을 명시, lock 파일 실제 이름.
- C9 드라이브 폴더 캐시: '증빙관리' 폴더를 옮기거나 휴지통에 넣으면 예전 ID로 계속 업로드 → 업로드 전 trashed 확인, README 경고.

## D. AI·MCP

- D1 채팅 안내문에 입력 제안 예시("5/20 ABC식당 회의비 85,000원 집행 기록해줘"), 외부 전송·비용·첫 응답 지연 고지, "대화 지우기" 권장. 대화 기록은 최근 N개만 전송.
- D2 제안 카드: 신규 제안도 폼에 못 채운 값 경고(현재는 수정 제안만), 행 수정 카드에 "exec 행 12" 대신 거래번호·거래처·금액·이전값→새값 표시, 제안 id를 대화 전체에서 유일하게, 폼 취소 시 카드 상태 표시. 도구 스키마의 fund/tags를 실제 목록 enum으로.
- D3 오류 한국어화: 400/404/529 안내, 타임아웃을 네트워크 오류와 분리, 실패 시 질문 텍스트 복원.
- D4 영수증 추출: 기존 입력 덮어쓰지 않기, 채운 칸 하이라이트, 신뢰도 한글, 증빙번호를 관리번호에 넣지 않기, 추출에 쓴 파일을 증빙으로 바로 연결하는 옵션.
- D5 보고서: 서버 집계(build_dashboard)를 주입해 모델은 서술만, 마크다운 표 렌더링, "수치는 대시보드와 대조" 고정 문구.
- D6 OpenAI 호환: 설정 화면에 제약(도구 호출·이미지 필요, PDF 불가, 컨텍스트 크기) 표시, 연결 확인에 도구 호출 1회 포함, reasoning_effort는 추론 모델에만.
- D7 MCP: 조회 도구 readOnlyHint, 삭제·수정 destructiveHint, `LEDGER_MCP_READONLY` 옵션, list_* limit/offset, get_exec(거래번호), 예산목·결제수단 Literal, docstring에 재원코드·태그 규칙·금액 단위. README에 "MCP는 제안 카드 같은 확인 단계가 없음" 명시.

## E. 받아들이지 않거나 보류한 지적 (Fable 판단)

- 백업을 5분 간격으로 줄이자 → 저장마다 백업은 xlsx 단일 파일 구조의 핵심 안전장치. 대신 "일별 첫 백업 별도 보존"만 수용.
- 재원/연도 변경 시 거래번호 재부여 → 증빙 폴더·적립금 연결이 번호 기준이라 재부여는 위험. 경고 + 삭제 후 재입력 안내가 적절.
- 적립 행 삭제도 집행처럼 차단 → 적립 실수 정정이 필요하므로 차단보다 "연결 집행 함께 삭제" 옵션이 맞음.
- 토스트를 하단으로 이동 → 취향 문제. 동일 메시지 병합(겹침 방지)만 수용.
- 예산에 연도 구분 도입 → 설계 결정(재원 기준 예산)을 바꾸는 사안이라 사용자 결정 필요. 우선은 안내 문구로 대응.

## 제안하는 작업 순서

1. A1·A2·A3·A6·A7·A8 (반나절) — 화면 입력 신뢰성 회복. 특히 A1은 예산 입력 자체가 막혀 있음.
2. A4·A5·A10·A11·A12·A14 — MCP·드라이브·시작 안정성.
3. B1·B2·B3·B5·B9·B12 — 입력 효율과 용어 정리 (한 묶음으로 설계).
4. B4·B10·B7 — 표·대시보드·마감 자료.
5. C(문서·설정) — README 전면 재작성, 설정 패널 재배치.
6. D(AI·MCP) — 비용·안내·오류 처리, MCP 보호.

리뷰 에이전트 작업 메모: 모두 스크래치 폴더만 사용. 한 에이전트가 다른 에이전트의 스크래치 스크립트를 잠시 옮겼다가 복원했다고 보고함(프로젝트 영향 없음). 테스트 중 생긴 `app/__pycache__`는 삭제 대상.
