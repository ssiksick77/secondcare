# SECONDCare 리눅스 서버 이전 준비 (2026-11-04)

결정 (2026-11-04, 사용자): Docker 로 띄운다. 공용 리눅스 서버, 내 계정만, root 없음. Tailscale 은 compose 사이드카(userspace 모드)로 돌리고, 앱은 그 컨테이너의 네트워크를 같이 써서 호스트에는 포트를 하나도 열지 않는다 (127.0.0.1 도 다른 계정이 접근할 수 있으므로). 데이터는 `~/secondcare/data` (chmod 700). 접속 방식 확정: Tailscale 사이드카 + Node sharing (Personal 플랜, 무료). 사용자는 tailnet 에 초대하지 않고 각자 개인 계정으로 `secondcare` 노드를 공유받는다. 자동 검사(`scripts/check.sh`)는 서버에서 돌리지 않는다.

## 1. 코드 조사 결과

이식성은 대부분 이미 갖춰져 있다.

| 항목 | 상태 |
|---|---|
| 파일 잠금 (`store._file_lock`) | Windows `msvcrt`, 그 외 `fcntl` 분기 있음. 리눅스에서 그대로 동작 |
| 장부·설정·채팅 경로 | `LEDGER_DB`, `LEDGER_ENV`, `LEDGER_CHAT_DB` 환경변수로 이미 옮길 수 있음 |
| 백업 폴더, 구글 토큰·클라이언트·폴더 캐시 | `app/` 옆 고정 경로. 코드를 고치지 않고 Dockerfile 의 심볼릭 링크로 `/data` 에 둔다 |
| 서버 주소 | `127.0.0.1` 고정. 앱이 tailscale 컨테이너와 네트워크를 공유하므로 그대로 둔다 (`tailscale serve` 가 127.0.0.1:8791 로 넘김) |
| 오류 때 `input()` 대기 | 콘솔이 없는 서버에서 EOFError → stdin 이 터미널일 때만 기다리게 고침 |
| `pystray`, `pillow` | 트레이 전용. 서버 이미지에서는 뺀다 |
| `.bat` 실행기 | Windows 전용. 서버는 compose 가 대신한다 |
| 구글 로그인 리다이렉트 | `LEDGER_OAUTH_REDIRECT` 로 이미 설정 가능. 127.0.0.1 이 아니면 구글이 HTTPS 를 요구함 |
| 나가는 연결 (구글·Anthropic·OpenAI API) | 사이드카의 일반 인터넷으로 나간다. userspace 모드 제약(tailnet 으로 나가는 연결은 프록시 필요)은 들어오는 접속만 받는 SECONDCare 에 영향 없음 |
| 드라이브 첫 연결 (`drive.connect`) | `run_local_server(open_browser=True)` 는 브라우저가 있는 PC 에서만 됨. 토큰은 PC 에서 만들어 복사한다 |
| MCP 서버 (`mcp_server.py`) | stdio 로 Claude Desktop 이 같은 PC 에서 띄우는 구조. 서버 장부를 보려면 서버에서 실행해야 하며 이번 범위 밖 |

## 2. 추가한 파일

- `deploy/Dockerfile`: `python:3.12-slim`, `app/` 복사, 트레이 패키지 제외. `backup/`, `google_token.json`, `google_client_secret.json`, `google_oauth_client.json`, `drive_folders.json`, `google_token.expired` 는 `/data/…` 로 가는 심볼릭 링크.
- `deploy/docker-compose.yml`: `tailscale` 서비스 (`tailscale/tailscale`, `TS_USERSPACE=true`, 상태는 `~/secondcare/tailscale`, `TS_SERVE_CONFIG`) 와 `secondcare` 서비스 (`network_mode: service:tailscale`, `~/secondcare/data` → `/data`, `LEDGER_DB=/data/secondcare_aic_2026.sqlite`). `ports` 없음.
- `deploy/serve.json`: `tailscale serve` 설정. 443 HTTPS → `http://127.0.0.1:8791`.
- `deploy/.env` (gitignore): `SECONDCARE_HOME=/data/<계정>/secondcare` (기준 폴더; 비우면 `~/secondcare`) 와 `TS_AUTHKEY=tskey-auth-…`. `tag:secondcare` 로 발급한 인증 키. 노드는 `TS_HOSTNAME=secondcare`, `TS_EXTRA_ARGS=--advertise-tags=tag:secondcare` 로 태그 노드로 올라가며, 태그 노드는 키 만료가 자동으로 꺼진다.
- `.dockerignore`: `app/` 만 빌드 컨텍스트에 넣고 비밀·백업·장부는 제외.

`/data` 안에는 이것이 들어간다 (모두 git 밖):

```
$SECONDCARE_HOME/               (예: /data/<계정>/secondcare)
  repo/                                  # git clone 한 저장소
  tailscale/                             # 사이드카 상태
  data/                                  # chmod 700
  secondcare_aic_2026.sqlite             # 장부. 연도별 파일은 같은 폴더 (secondcare_aic_2027.sqlite …)
  .env                                   # app/.env 그대로. LEDGER_OAUTH_REDIRECT 만 바꿈
  google_client_secret.json              # OAuth 클라이언트 (드라이브·로그인 공용)
  google_token.json                      # 드라이브 토큰 (PC 에서 연결 뒤 복사)
  backup/                                # 저장 전 자동 백업 (앱이 만듦)
  chats.sqlite                           # AI 채팅방 (앱이 만듦)
```

## 3. 서버 준비 순서

1. 내 계정에서 Docker 를 쓸 수 있는지 본다 (`docker compose version`). root 가 없으면 관리자에게 docker 그룹 추가를 받거나 rootless Docker 를 설치한다. 서버에 Tailscale 을 설치할 필요는 없다 (사이드카).
2. 저장소를 받는다 (3 의 위치). 장부·비밀 파일은 git 에 없으므로 따로 복사한다.
3. 기준 폴더를 정하고(`deploy/.env` 의 `SECONDCARE_HOME`, 비우면 `~/secondcare`) `mkdir -m 700 -p $SECONDCARE_HOME/data $SECONDCARE_HOME/tailscale` 뒤 위 파일들을 넣는다. 저장소는 `$SECONDCARE_HOME/repo` 에 받는다 (`git clone https://github.com/ssiksick77/secondcare.git repo`). 장부 파일 이름은 `secondcare_aic_<yyyy>.sqlite` (2026-11-04 결정; 옛 이름 `의료인공지능센터_지출장부_<yyyy>.sqlite` 는 복사하면서 바꾼다). `.env` 의 `LEDGER_DB` 도 새 이름으로. 장부는 Windows 앱을 끈 상태에서 복사한다 (`.sqlite-wal` 이 남아 있으면 같이).
4. `.env` 에서 `LEDGER_OAUTH_REDIRECT=https://<서버이름>.<tailnet>.ts.net/auth/callback` 로 바꾼다. 구글 클라우드 콘솔의 OAuth 클라이언트(웹 애플리케이션 유형)에도 같은 URI 를 추가한다. 데스크톱 앱 유형 클라이언트는 이 URI 를 받지 않는다 (README 2-1).
5. Tailscale 관리 콘솔을 준비한다.
   - Access controls 에 태그와 최소 정책을 넣는다. 공유받은 사람(`autogroup:shared`)은 `tag:secondcare` 의 443 만 열 수 있고 내 다른 기기에는 닿지 않는다:

     ```json
     {
       "tagOwners": { "tag:secondcare": ["autogroup:admin"] },
       "acls": [
         { "action": "accept", "src": ["autogroup:member"], "dst": ["*:*"] },
         { "action": "accept", "src": ["autogroup:shared"], "dst": ["tag:secondcare:443"] }
       ]
     }
     ```

   - DNS 탭에서 MagicDNS 와 HTTPS Certificates 를 켠다. 주소는 `https://secondcare.<내 tailnet>.ts.net` 으로 고정된다.
   - Settings → Keys 에서 `tag:secondcare` 태그로 인증 키를 만들어 `deploy/.env` 에 `TS_AUTHKEY=` 로 적는다.
6. 이미지를 만들고 띄운다:

   ```
   cd $SECONDCARE_HOME/repo
   docker compose -f deploy/docker-compose.yml up -d --build
   docker compose -f deploy/docker-compose.yml logs -f
   ```

   콘솔에 `장부 파일: /data/...`, `로그인: 구글 로그인, 허용 N명, 리다이렉트 https://...` 가 보이면 된다.
7. `docker exec secondcare-tailscale tailscale status` 로 접속 상태와 이름을 보고, `docker exec secondcare-tailscale tailscale serve status` 로 443 → 127.0.0.1:8791 이 잡혔는지 본다. `https://secondcare.<tailnet>.ts.net` 으로 접속하고 구글 로그인을 한 번 한다. HTTPS 인증서는 Tailscale 이 준다. 호스트에서는 `curl http://127.0.0.1:8791` 이 되지 않아야 정상이다.
8. 증빙 업로드를 한 번 해서 드라이브 토큰이 갱신되는지 본다. `google_token.expired` 가 생기면 PC 에서 다시 연결해 토큰을 복사한다.
9. 저장을 한 번 하고 `$SECONDCARE_HOME/data/backup/` 에 백업이 쌓이는지 본다.

## 4. 사용자 공유 (관리자)

사용자 12명은 tailnet 에 초대하지 않는다. 콘솔 Machines → `secondcare` → Share 로 한 명씩 공유한다. 공유 목록이 곧 접근 목록이다. 퇴사·변경은 공유 해제로 처리하고, 앱의 로그인 허용 목록(설정 → 로그인 허용 계정)도 같이 정리한다.

## 5. 전환 당일

1. Windows 앱(트레이)을 끄고 시작 프로그램 등록을 푼다 (`app/uninstall_startup.bat`).
2. 최신 장부를 3 번처럼 다시 복사한다.
3. 서버를 띄우고 7~9 를 다시 확인한다.
4. 사용자에게 새 주소를 알린다. 옛 주소(`127.0.0.1:8791`)는 더 쓰지 않는다.

되돌리기: 서버를 내리고(`docker compose down`) `/data` 의 장부를 Windows 로 복사해 `app\run.bat` 로 띄운다. 코드 변경은 Windows 실행에 영향이 없다.

## 6. 사용자 안내

1. Tailscale 을 설치한다 (<https://tailscale.com/download>, Windows·Mac·휴대폰).
2. 무료 개인 계정을 만든다 (구글 계정으로 가입 가능). 회사 tailnet 에 들어가는 것이 아니라 본인 계정이다.
3. 담당자가 보낸 공유 수락 링크를 열고 "Accept" 를 누른다. 본인 기기에서 Tailscale 이 켜져 있어야 한다.
4. 브라우저에서 `https://secondcare.<tailnet>.ts.net` 을 연다 (즐겨찾기 권장).
5. "Google 계정으로 로그인" 을 누르고, 담당자가 허용한 구글 계정으로 들어간다.

## 7. 아직 안 한 것

- `$SECONDCARE_HOME/data/` 의 바깥 백업 (다른 디스크나 드라이브로). 앱의 자동 백업은 같은 폴더에 30개만 남긴다.
- 컨테이너 안에서는 root 로 실행된다 (호스트 계정 권한 안에서; rootless Docker 면 호스트의 내 계정으로 매핑). 데이터 폴더가 700 이라 다른 계정은 못 본다.
- Tailscale 대신 도메인 + Caddy/nginx 로 바뀌면 사이드카 대신 리버스 프록시가 들어가고 4 의 URI 만 달라진다.
- MCP 서버를 서버에서 쓰는 방법.
- `docker compose up` 은 이 PC 에 Docker 가 없어 아직 실제로 실행해 보지 않았다.
